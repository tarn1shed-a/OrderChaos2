# 移动延迟的分段测量

2026-11-13。只测量宿主传输/呈现开销，不修改原指令、移动速度、50ms 游戏步长、碰撞、相机或存档。自动任务 2 保持暂停。旧公开二维首页入口已撤下；现有三维预览的进入窗口仍非原版登录页。

`deploy/observe_server.mjs` 对完整 SHA 固定的已审核服务器文本生成独立诊断副本，原文件和私有包保持不变。`movement_trace.mjs` 仅对带数字序号的测试输入，记录本连接接收、接受输入、开始/结束移动计算与回复时间；不记录名字、坐标、凭据或存档。普通连接不会收到诊断字段。浏览器仅在 `?timing=1` 启用 `browser_timing.mjs`，观察真实按键和同帧角色/相机呈现，结果放在 canvas 的开发属性里，无新增可见界面、外发日志或预测移动。

每条样本的时间应相加核对：按键→首次发送、首次发送→被回复的输入发送、该输入→状态回包、回包→渲染提交。第二段用于说明周期输入覆盖了尚未处理的前一次输入，不能漏掉后宣称分段之和就是总时间。服务器段分为输入处理、等待原定时器、移动计算（含原 CPU/线程通信）和移动后至回复。客户端往返减服务器段，仍包含网络、代理及服务器开始处理前的事件循环等待，不能将其冒称纯网络或精确单程延迟。渲染提交也不等于显示器扫描完成。

本地 Linux，单连接与双连接各 12 次，输入发送到状态回包中位数分别 60.0ms、59.7ms；原移动调用中位数分别 18.1ms、17.0ms。双连接第一人的移动完成后还等待第二人计算，再收到同一完整房间状态，中位 18.6ms。单次分段可以相加；各段独立中位数不保证相加等于总中位数。这些数据不是 Railway 实机性能。

`tools/movement_timing_probe.mjs` 只接受显式指定的既有测试身份回执；测试角色位置会随真实输入正常保存，不登录用户主角色。原始回执、按键报告、画面、备份与云端部署回执留在 `analysis/raw/latency-breakdown-20261113/`，不上传 GitHub。后续以同一次输入的线上实测决定是否还有符合“不改游戏逻辑和画面”的优化，不能直接拿不同日期的网络 ping 和移动中位数相减。
