# 全角色选择的接线与验收

2026-11-15。总目标仍是所有原版允许的角色可选择、创建、恢复并实际进入游戏；以下按实际完成范围记录，不能把选角测试当作全部角色可玩。原数据与45项列表见 `PLAYER_CHOICE_RECOVERY.md`。

## 真实原界面检查

原 `CharacterChooseRace`、`CharacterChooseClass`、`CharacterChoosePart` 和选角列表，逐项点击9种身体×5职业，共45项。每项经过种族/允许的性别、职业、命名、创建按钮，实际HTTP请求与落盘的 `profession/sourceAvatar` 完全对应。每种身体的五个角色再实际刷新、逐个选中，并核对原职业图标。龙人按原界面仅显示一种性别。

这是9个独立本地测试来源，各5个角色，未清空真实浏览器存储，保留原网页32条凭据限制。没有点击开始，也没有3D、物理或WS服务，因此该批仅确认选角、创建和保存/读取。共54张实际截图、38项离线检查通过；9个测试页面和9个轻量服务已关闭。

私有交接为 `analysis/raw/player-choice-ui-20261115/handoff.json`，SHA256 `47e25dec4a2dc628135fb02518b8ab303924e086827cee90566f1faa44eb6367`。131件材料的清单与原资源、角色凭据、截图均留在忽略目录。测试工具是 `tools/player_choice_ui_qa.mjs`；其预检最后一项只适用于创建前的运行中服务，不能在45项创建完成后重复当作最终验收。公开CI仅运行不依赖这些服务的检查。

## 地图服务不再丢弃所选身体的数据

原普通任务的 `quest_motion.mjs` 只发送位置、速度和跳跃，未发送所选身体或明确的前进控制，也未把原动作/完整姿势带回快照。此前人类男性联验用私有副本补过这条线路。本批将它整理为默认关闭的共享接线，不改变旧角色路线：

```js
const choice = playerChoiceMotion({registry, bodies: [{
  profile: verifiedSpeciesProfile,
  pose: {field: 'sourceHumanPose', bindingId, valueBytes: 1992,
         decode: sourceHumanPose},
}]});
const motion = createQuestMotion(config, threadURL, entry, {playerChoice: choice});
```

`bodies` 只包含已核查且该worker真实提供的身体，不能传45项目录就开放45个模型。worker启动须宣布相同身体、绑定ID和字节数；reset使用该角色自己的种族，tick传入明确前进控制，返回的动作必须指向自己的原轨道。完整姿势经既有严格解码器验证后，才与位置一起更新。活动演员不能换身体/职业，跨演员、跨身体、重复姿势字段均拒绝；房间fork保持独立原生演员范围。

共享桥使用真实人类男性worker、原map1碰撞与既有原资料，实际执行两个演员、每人12tick，收到各自完整135属性/1992字节姿势。没有改动配置、原文件或存档。证据在 `analysis/raw/player-choice-motion-20261115/parent-check-v1/receipt.json`。公开边界测试使用明确的RPC夹具，不能冒充原物理；另有一个私有冻结原姿势包的逐字节传输检查。

人类女性另有自己的131属性/1928字节绑定，不能套男性包。它和其他身体需要各自实际入图与浏览器验收，未在本批统一开放。

## 一起修正的角色切换问题

- 旧角色的任务回包在切换/重连后整体作废，不再只拦状态却继续显示旧任务正文。
- 点地移动与朝向使用原世界的横向坐标，避免长宽比例不同的地图窗口把方向和动画速度扭曲。

两项都执行真实客户端函数的边界检查。矩形地图的实际走动检查发生在隔离8936页面，穿过区块边界、走到海岸，未改用户位置或任务审批。截图为私有 `mainline-scene-20261115/qa-v2/actual-coast-walk.png`，不是Railway已发布效果。

## 仍须继续
