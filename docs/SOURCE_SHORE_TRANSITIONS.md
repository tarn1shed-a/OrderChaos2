# 游泳、浅水移动与上岸动作衔接

后续核对更正：本节关于 `run_normal` 是该原RUN分支最终动作的判断不充分。原动作初始化表实际映射到 `run_normal_front`；当前预览已按原表纠正，原状态提交和普通混合的新增证据见 [动作切换与混合](SOURCE_LOCOMOTION_BLENDING.md)。本节其余内容保留为上一轮记录，不把旧缓存名字当成实际动作选择。

2026-11-11，基线 `6d9a61e`。本轮修正**浅水里误播跳跃动作**的接线错误，接回原普通移动判断和原 `run_normal` 动作。实际完成深水→浅水→岸上→返回水里，再次上岸、双端核对和刷新恢复。光源、天气、地图、碰撞几何、旧美术及布局不改，自动任务2保持暂停。

## 原因

旧网页用 `!grounded` 创建跳跃播放记录，而这里的 `grounded` 只是宿主用“竖直速度和加速度均为零”计算的标记，**不是原版的动作状态，也不是原地面接触判定**。上浮恰好进入浅水的那一帧仍可能有竖直速度，原动作仍是普通移动，网页却自行创建了 `jump_air`。另外，旧输入接线在回到陆地后仍保留上一帧的游泳竖直速度，没有经过已找到的原普通输入检查。

本轮没有把“浅水”硬设为落地，也没有按固定水深、固定高度或地形距离强行播放站立。原碰撞和游泳判断继续产生位置及水域状态；只有原跳跃/下落状态且尚未结束时，宿主才建立对应的空中播放记录。

## 实际验收

使用两个新增独立验收角色，未改主角色出生点或存档。鼠标转镜，键盘实际从原水位110的水域出发：深水状态4/游泳高度108.550003，进入浅水状态3后播放 `run_normal`，再走上干地状态0；返回水里恢复 `swim_idle/swim_forward`。再次上岸后停在原查询高度112.172470，刷新后坐标、高度和水域状态完全恢复。另一连接在静止阶段收到完全相同的坐标/高度/水域状态；临时端口的独立双WebSocket检查也通过。

第二次浅水移动实测恰好捕获到旧宿主`grounded=false`，而原普通姿态仍32、原跑动正常、跳跃高度为0：这正是过去会误播跳跃的边界，不能把它改写成“所有浅水帧grounded=true”。原输入检查在下一次普通输入接管；不修改原碰撞的位置结果。

浏览器首轮发现其他场景模型没有玩家的 `run_normal`，已修正为保留这些模型既有控制器，再重新载入完成验收。最终页面无warn/error。截图里的大片单色地表、岸边材质和镜头局部遮挡属于原先未完成的显示缺口，本轮没有用新美术或调光遮盖，也不据此宣称地图画面已1:1。

9项新增检查、8项潜水回归、14项游泳回归、9项原物理回归共40项本地通过。新增检查覆盖旧浅水坐标/残留竖直速度、原输入守卫、实际缓岸往返、真实跳跃/桥边下落不被抹平、原跑动重新导出、真实骨骼的游泳→跑动→站立→跳跃转换、旧素材/主存档/暂停状态。三套临时端口/临时存档检查分别覆盖本轮岸边、既有潜水和桥面跳跃/落地/重连；不触碰朋友数据库。
