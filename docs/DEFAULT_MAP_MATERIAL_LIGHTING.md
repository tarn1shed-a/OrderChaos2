## 默认配置与找到的显示差异

APK Default 与 GPU_6 不同：模型等六个键相同，但 GPU_6 额外开启 EnableBloomHDR。新工具的 APK_Default 执行原默认读取器和空覆盖分支，不再拿 GPU_6 冒充默认值。

| 原 APK 默认声明 | 本轮处理 |
| --- | --- |
| ModelDetailLevel=0、ForceModelLodLevel=0、DeviceLayer=5 | 沿原消费把 DeviceLayer 限制为 4，槽 0 普通模型 |
| ShowModelLightMap=true、ShowTerrainLightMap=true | 分别按原实例 DAT/图页和地块光照请求绑定 |
| MEM/Default UseSmallTerrainMask=false | 普通 .msk；没有 _l 遮罩替代或自绘遮罩 |
| EnableRTTCreating=true、RTTViewportScale=1 | 默认中间目标及全视口 |
| EnableBloom=true、EnableBloomHDR=false | 使用原非 HDR 后处理 |

原 `0x345c2c` 依据 HDR 字节选择 pe_rtt/RGB8（格式 12）或 pe_rtt_HDR/RGBA16F（格式 30）。原 `0x346574` 的 `0x34782c–0x347890` 将普通 Bloom 组合为修饰位 0x10，即 HAS_BLOOM；HDR Bloom 则为 0x6000，即 HAS_BLOOM_HDR 和 COLOR_GRADING。后者不属于此默认普通帧分支。格式名、宏表、完整例程均按原字节/重定位核对，没凭宏名猜选择。

旧预览始终使用半浮点 HDR、Reinhardt、LUT 和 HDR 七点模糊。本轮改用原包中的 pe_common_vs.glsl / pe_common_fs.glsl：

1. 普通下采样/亮度提取，五个采样，原 HAS_ADJUST_BY_LUMIN。
2. 原四点水平、垂直模糊，各 11/32、5/32 权重。
3. 原普通 Bloom 合成 `base + bloom * (1-base)`；不使用 HDR 或 LUT。

原 `0x34aa30` 的提取强度为 `(colorDecrease + sqrt(intensity)) * float32(0.2)`，不是旧 HDR 的阈值/强度处理。当前区域 195 对应 decrease=0.3944999874、intensity=1.2617000341，原算术和浏览器都得到 0.3035508394。偏移常数、四分之一尺寸、RGB8/RGBA8精度来自原声明/代码；不换成自行选择的滤镜。

原 GLSL 全文只写入忽略的本地素材。公开 JS 只负责机械的 WebGL2 语法/属性接入：attribute/varying、输出变量、texture2D 和与 GLSL 300 函数冲突的原 texture 采样器名称。场景 RGB8 在浏览器用 RGBA8、未使用 alpha=1 表示，RGB 精度相同。没有添加曝光补偿、环境灯或美术。

## 材质、UV 与图像核对

范围仍为九块研究地形、39 条实例，不冒充整个新手地图、原出生点或原驻留窗口。

- 从原 BDAE 重新解析 16 个模型，50 份材质的名字、采样器与旧转换资料完全一致。
- 原顶点、法线、索引、分组、UV0、UV1 与保留转换流逐项相同。
- 17 张颜色贴图重新解码，与预览 PNG 的全部 RGBA 像素相同。该检查不代表浏览器 mip/各向异性就是原设备采样。
- 沿本轮 APK_Default 重新执行创建前过滤，核对原实例 TRS、模型源 SHA、地形高程及普通遮罩，按槽 0 的 DAT/原实例 ID、图页和 UV 参数生成绑定，39 条均可接入。

这些结果未发现“颜色图被换成了另一张图片”或“UV 流被改写”的证据。因此没有盲目重建已经匹配的原几何和美术。错误的后处理则已直接重构。

## 偏暗定位：已证实什么

同一角色、相同位置/视角，以修改前后 495×848 截图比较背景区域，亮度只略变。例：地面区域 RGB 均值从约 (25.90,21.69,18.92) 到 (26.18,21.73,19.57)。HDR/LUT 差异确实存在，但不是这块画面偏暗的主要解释。

新增一次性离屏诊断，只写开发记录，不显示游戏面板。对画面归一化位置 (0.7,0.7)，实际命中实例 715733704、god_temple04 的材质 0：

| 阶段 | 实测 |
| --- | --- |
| 颜色图 god_all_l 的当前采样 | RGB8 约 (32,40,48) |
| 实例原图页 -41_2.tga 的当前采样 | RGB8 约 (22,22,28) |
| 插值后的全局光照/色调增益 | 约 (1.835,1.396,1.145)，诊断按 /4 编码后读回，含 8 位量化误差 |
| 进入后处理前的场景像素 | RGB8 (5,5,6) |
| 该位置 Bloom | (0,0,0)，普通合成没有继续压暗 |

这闭合了**当前预览**的暗色来自颜色图×图页×顶点光照阶段，而非只在屏幕合成时变暗。离屏分项是诊断实验，不冒充原 Android 帧或原 GPU 捕获。原着色文件也有这些乘法，但尚不能仅凭它断言此处已经与原版完全一致。

仍未闭合：原环境 RGB 后续叠加/天气状态、全部材质变体和阴影路径、完整纹理 mip/采样，以及同位置原版帧对照。现有镜头/移动、区域环境的部分播放适配仍为历史原型。没有凭肉眼修改这些未知值，也不把“仍暗”当成原资源包损坏或模拟器不够强。

后续更正：本页的离屏读数是在加载第10帧保留的固定镜头实验，不能代表角色移动后的当前画面；不据此声称与后续截图是同一个最终镜头。采样刷新、原环境/天气新证据与仍暗的实际验收见[原默认环境光、天气与偏暗核对](DEFAULT_ENVIRONMENT_WEATHER.md)。
