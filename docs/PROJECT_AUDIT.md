## 本轮重现与测试结果

### 隔离重建

本轮用现有构建代码把输出写入审计临时目录，没有覆盖 `game-data/converted/`：

- 读取380个包内输入及2个松散字体，生成320个文件；当前转换目录有322个文件。
- 313个文件逐字节相同，其中包括全部22个模型和270张PNG。
- 2个拉丁WOFF只有head表时间戳和相应checksum不同；其余字体表、glyph顺序和cmap相同，去掉这些元数据后head也相同。
- 2份字体/界面JSON只有本地所需字覆盖计数710→714的变化，不是原字形变化。
- 3个素材库文件受生成时间、条目数及顺序索引变化影响。
- 当前目录额外保留 `ui/basic-attack-79.png` 和 `ui/basic-attack-80.png`，本轮干净重建不再生成；应视为待清理的旧产物，本轮未删除。

这两张旧图只被素材库目录引用，未在当前玩法配置中找到引用。当前目录319条素材记录、干净重建317条记录的文件长度/SHA均匹配；两份输出各检查653个资源URL引用，未发现缺失。这里只核对引用存在与摘要一致，不证明素材语义或原画面一致。

这证明现有转换的来源和可复现范围，不能单靠“重建相同”证明字段解释或原引擎等效。详细差异见本地 `rebuild-report.json` 与 `font-rebuild-diff.json`。

### 已有检查的含义

本地67个Python测试入口执行469项，0跳过、0失败；42个Node测试文件执行198项，0失败。测试和夹具共110个仓库文件，另1个Node文件是fixture而非独立测试入口。

Python检查混合了原文件/原指令集成验证与合成输入。Node检查主要证明本项目实现、局部数值/数据接线、同步及存档一致性。没有原游戏服务器或完整原Android/OpenGL进程作为对照，所以不能把这些数字换算成“恢复了多少原系统”。CI在缺少私有原文件时还会跳过相应检查，CI成功尤其不能代替原样本验证。

### 发现的校验失败

**本轮不是所有检查都通过。** 独立运行现有 `tools/verify_resource_preview.py`，对当前目录与隔离重建目录均在第262行失败：它仍断言素材库的 `sourceFormats` 只能包含旧的7个字段，而现有输出还包含 `sceneBakedLighting` 和 `terrainLighting`。旧字段的值没有差异，失败原因是校验器的字段集合断言过期。

现有CI/单元测试未直接调用这个总校验入口，因此单元测试全过没有暴露该失败。总校验在这里中止，不能声称其后续循环已执行；上面的资源URL和素材SHA检查是本轮另行完成的核验。日志见本地 `current-verify-errors.log`、`rebuilt-verify-errors.log` 和 `independent-resource-check.json`。本轮只登记缺陷，没有修改校验器。
