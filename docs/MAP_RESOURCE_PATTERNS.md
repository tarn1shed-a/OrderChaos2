# 新手地图文件与复用规律

本笔记整理到2026-11-12已核对的客户端资料，服务后续逆向。完整清单和原文件仅在本地忽略目录，以下是结构摘要；不把可读取文件等同于原客户端已经创建或显示成功。

## 文件如何连在一起

| 原资料 | 已核对的作用 | 查找/核对重点 |
| --- | --- | --- |
| 地图world容器 | 地图名、配置及地块框架 | 先看原请求入口和配置选择，不由浏览器场景猜地图名 |
| world/tutorial/terrain/*.trn | 每地块高度/法线/颜色、区块纹理与水字段等 | 按原记录/引用读取；251块有源数据不等于同时全部驻留 |
| world/tutorial/layers/*.msk | 地表分层遮罩 | 配合原区块引用和采样分支，不能按图片尺寸猜层序 |
| world/tutorial/items/*.itm | 对象ID、类型、模型路径、位置/旋转/缩放、地块 | (地块, ID)才是预览核对键；原数据有跨地块复用ID |
| model/scene/**/*.bdae | 几何、primitive窗口、节点引用、材质及参数 | ZIP外包与内层BRES分别校验；模型文件不是只有顶点 |
| ut_*/lt_*.bdae效果文件 | 两profile、命名technique、pass状态、shader文件/宏、默认参数 | 与模型内参数覆盖分开，不能从文件名猜最终效果 |
| *.glsl | 宏控制下的实际着色算式 | 先确认宏与输入来源，再连接相应分支 |
| world/tutorial/lightmap/*.dat | 按对象ID/模型槽查图页和UV参数 | 用当前所选槽；同名_l不是可以任意借用的后备 |
| texture/lightmap/.../*.tga | 原图集像素 | 后缀tga可能实际是PVR或透明split容器；由字节验证格式 |
| 模型同路径*.phy | 原静态碰撞形状 | 独立于美术；不能根据显示模型自行造碰撞 |

简化链路是：**ITM选对象 → BDAE节点和材质 → FX宏/状态 → shader与纹理**，另由**地块+对象ID+槽位 → DAT → 图页/UV**提供实例绑定。地形/水面和PHY各有自己的原加载链，不能混成一条通用“贴图加载”。

## 这批112条揭示的规律

1. **优先按材质族分组。** 112条只涉及20种模型；其中45条共用带VERTEX_ANIM的材质族，31条复用同一plane模型。本轮一个静态LIGHTMAP_GRAY分支就解开3种模型/9条摆放。先恢复共用分支，再逐个核对实例，比按数量逐条猜更有效。
2. **模型参数会覆盖效果默认。** 灰度效果默认比例0.15；大针叶树模型明确写0.20。每个材质都需要核对具名属性、源类型、数组数量、状态和数据，不能给整个材质族写同一个常量。
3. **名字相似不代表算式相同。** LIGHTMAP_GRAY实际混合图集RGB与指定颜色，不是把颜色贴图去色。shake分支另读TexCoord2、WorldT、time与shakeSpeed；原shader在MEDIUM_END/LOW_END还会取消VERTEX_ANIM，实际宏来源未查清时不能挑一个看起来合适的分支。
4. **节点引用类型决定接法。** 当前静态模型读取器支持类型3的显式mesh引用；两种旗帜是类型2的#…-mesh-skin引用。不能以单位矩阵补上绑定，或用一帧静态形状冒称旗帜动画已恢复。
5. **缺口要定位到“缺哪条引用”。** 那7条DAT文件存在，缺的是槽0中的对象记录，槽1均能找到。记录缺失、纹理文件缺失、原资源创建失败是三件不同的事；只列实际观察到的一层，不替原客户端猜结果。
6. **显示和行走分开验收。** 本轮部分新增草木处于既有PHY/inside缺口地块，可显示但预览限制移动。必须记录输入后的实际位移，不能看到跑步动作就算走通；也不为走通而改场景或取消限制。

## 读取器里可复用的细节

以下偏移仅适用于已核对的BDAE版本0,0,0,946；节点引用类型与ITM对象类型属于不同结构的枚举，不能混用。

- 模型材质记录80字节，属性记录32字节。本轮灰度值在模型属性中：类型在+16、数量+20、状态相对指针+24、值相对指针+28。
- FX参数同样有32字节记录，但类型在+8、数量+16、状态指针+20、值指针+24。结构相似、字段偏移不同，不能直接复用模型属性偏移。
- source type8标量、type10三浮点经原112920c的类型/转换表到13e0b30。实际原CPU写入核对提供了比“这些字节看起来像浮点数”更强的证据。
- 采样值255是跳过setter，0是显式枚举。源文件有mip链也不代表原设备实际上传/使用了它；现有网页滤波/缓存仍有适配边界。
- 命名technique记录的首字2不是technique序号；原查找读+8名称。两份FX profile若有分支差异，不能未经原配置证据择一；本轮静态灰度分支核对两份一致后接入。
- 原文件CRC与包内长度先验证；外层资源SHA、解压BRES缓冲SHA、转换结果SHA分别保存。压缩前后SHA不同是不同对象的身份记录，不能混用。

## 摇动材质这一轮新增的规律（2026-11-12）

1. **先核对模型覆盖值，再花时间追动态输入。** 45条同类草木中，9种模型/44条明确写shakeSpeed=0；仅pinetree001的1条为0.8。名字带shake或存在VERTEX_ANIM不等于最后有位移。零值按原公式在各质量分支都不动，非零实例不能借这个结论。
2. **source语义、runtime语义和属性序号是三种编号。** 本轮TexCoord2对应source6、runtime3，但实际attributeIndex4。几何stride48或64，UV2偏移都40。必须从每primitive绑定和声明取值，不能用“第三套UV就是第三个属性”猜位置。
3. **常量化只适用于可证明等价的分支。** 原零速给零位移，不需要造时钟或风；非零分支还要闭合实际质量宏、时钟初始化和每帧矩阵提交。原CPU容器写入成功也不等于Android GPU上传成功。
4. **结构相似仍要按不同字段读取。** 材质80字节/属性32字节、FX的另一套属性偏移继续沿用前表；顶点描述另由stride/offset/type/component四张表定位，UV2在此版本为type6 float2。所有浮点保持源float32，不用四舍五入后的展示值生成数据。
5. **保留原数据，限制接入边界。** 新转换文件增加sourceUV2与语义说明，已有2327素材不重写。浏览器只接受带原参数复制证据的零速分支；动态1条仍拒绝，避免一种材质支持扩大成所有同名族都支持。

## 非零摇动分支的复用规律（2026-11-12）

1. **把材质参数、顶点幅度、帧输入分开查。** 此模型有4份材质，只有3份带原0.8速度；UV2.y平方给逐顶点幅度，time给相位，WorldT给带原缩放的方向。共享同一模型也不能让树干一并动，或给全部顶点同样幅度。
2. **时钟单位要追到消费者。** 原提供器微秒→整数毫秒→float32/uint32→float32秒；直接把Date.now的毫秒或累计delta秒送入shader会改周期/相位和舍入。宿主时钟起点与原安卓现场分开标注，刷新不假装恢复了旧进程相位。
3. **矩阵名字要落实成原写入和读取。** 1413868(type2)复制世界矩阵，148cfc4(87)转置；不能见WorldT就猜成逆矩阵，也不能归一化其方向而丢掉原缩放。普通场景组合和GPU提交仍是宿主接口。
4. **预处理宏会让参数有值却完全不动。** 默认ShadersLevel2保留VERTEX_ANIM，0/1关闭。DCC_MAX会改变幅度基值，必须核对游戏项目宏表和效果，而不是启用导出工具分支。用户指定APK_Default与实际设备选择保持区别。
5. **材质克隆后的uniform要重新接。** 图集绑定会克隆材质并重建uniform；动态速度、WorldT和time要在实例上恢复，并逐次绘制提交。仅模板材质有参数或CPU相位变化，不足以证明GPU画面真在动。
6. **固定镜头加静态参照能排除假运动。** 本轮树冠像素变化，而同一画面石块逐像素相同；相机元数据完全一致。截图变化仍不能替代原Android设备的GPU精度证明。
7. **外包与解压校验要明确命名。** 本轮ut_lightmap_shake_trans原外包SHA以abe9开头，BRES缓冲以1509开头；前版混写已更正。先让错误引用被拒绝，再重新取证，不能删掉校验以完成导出。

## 31条平面揭示的规律（2026-11-12）

1. **先看最早决定结果的条件。** 原plane.tga是split纹理，四级alpha红通道全0；原参考值0，0≤0先丢弃，后续RGB光照不可达。不能为了“看到恢复效果”把透明度改大，也不需要自造公共光照来填这一支。
2. **文件名trans不等于开启混合。** ut_trans两份profile只有ALPHA_TEST，原blend位关闭，深度测试/写入开启、LEQUAL、双面。裁切与混合/透明排序要各看自己的原位和消费者。
3. **材质有没有采样器，比摆放有没有DAT更直接。** 此材质只有texture和CurrentTechnique，没有LIGHTMAP；31条里20条有图集记录、11条没有，都不能强行进入旧烘焙绑定。接回这31条时原1200条图集绑定保持。
4. **指针基址偏移不能漏。** 本轮参考值从源状态+36到运行状态+12，应用时缓存低层对象+0x4d0；驱动比低层对象早0x38，上传端因此读驱动+0x508。漏掉这层关系会把旧0.5常量误当成原平面的值。
5. **所有mip都核对后，才可对输出作等价简化。** 不只看PNG基级。浏览器还逐字节检查实际PNGalpha；出现任何非零alpha都拒绝恒丢弃接法，留待恢复RGB/排序，不能让新资源被静默隐藏。
6. **队列有缺口可以保留，但不能编顺序。** 原运行pass无blend位，消费者还读编译程序标志；显式flag夹具给出两条容器路线，不等于实际设备选择。此处颜色/深度无写使结果不依赖排序；完整原队列仍待恢复。
7. **摆放数量与可见像素分开统计。** 当前154模型、1231源摆放中含31条zeroAlphaInstances；不是新增31件可见美术。历史displayedInstances计图集绑定，不能跨材质族直接用作画面可见数。
