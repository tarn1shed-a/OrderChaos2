# 玩家存档与运行观察

2026-11-19 核查：生产服务已使用 `ON_FAILURE`，最多重试三次。隔离验收容器关闭自动重启，是为了保留首次失败和退出码；不代表生产也关闭。自动重启不能代替内存问题排查，也不能补回尚未提交的位置。

核心角色资料与任务账本使用同一写入顺序：在主文件同目录创建唯一临时文件，完整写入，执行文件 fsync、关闭文件，最后 rename 原子替换。加载器只读取指定主文件；写入中断留下的临时文件不会被提升成角色资料，损坏的主文件会报错，不以空档覆盖。

用实际原角色存储器和当前任务账本，在隔离临时目录分别于 rename 前后强制终止自有子进程，四次检查通过：主文件保持完整旧版或完整新版，另一角色保持；任务完成与奖励在同一账本提交，重读后重复提交不会重复奖励。测试没有制造真实 OOM，也没有修改生产角色或原审定代码。

位置只能恢复到最后一次成功提交。现有位置自动保存名义间隔为五秒，事件循环和错误可能使它延后。核心文件未对父目录执行 fsync；这次验证的是进程强杀时的单文件保护，不是整机断电持久性或跨文件事务保证。后台身份、删除备份和离线修复回执的独立窗口已登记，未把这些辅助文件包括在核心存档保证中。

上线时保留部署时间、存档摘要、cgroup 读数和 Railway Metrics 基线。Railway 持续记录内存曲线，可用 `railway metrics --memory --since 7d --raw --json` 回看；比较时应区分部署、负载、文件缓存和重启。短期无 OOM 不能证明多日无增长，仍需在运行数天后复查。旧自动续跑保持暂停。
