# 角色页共用结构与批量核对

2026-11-16，按同版本原客户端执行结果核对。前期逐组合扩展构造器过于分散；后续以共同引用结构和实际资源类型组织工作，不再为每个职业复制页面或整套渲染器。

## 原文件的分工

原界面不是每职业一份文件：种族页`CharacterChooseRace.swf`、职业页`CharacterChooseClass.swf`、外观页`CharacterChoosePart.swf`分别负责各阶段。五职业共用职业页；人物由`creaturedisplayinfo → creaturemodeldata / creaturedisplayinfoextra → itemdisplayinfo / itemmodeldata`选择身体、服装和武器。已有角色选择另用`CharacterChooseCharacter`，不能与新增角色三个阶段混为一页。

对45组职业页和45组外观页的冻结原代码输出一次性核对后：

| 核对项 | 职业页 | 外观页 |
|---|---:|---:|
| 组合 | 45 | 45 |
| 实际身体文件 | 9 | 9 |
| Model配置 | 18 | 9 |
| 衣服等槽位引用的独立文件 | 230 | 91 |
| 武器独立文件 | 6 | 6 |
| 实际武器加载请求 | 54 | 45 |
| 所有模型引用并集 | 245 | 106 |
| 有Model附加效果的组合 | 9 | 0 |

同一种族/性别的五职业共用身体文件，职业页九个法师组合使用另一条Model配置并带手部效果。职业页和外观页服装、持武器/收武器参数及相机不同，不能直接沿用前一页的人物结果。

## 批量处理方法

`tools/creation_structure_audit.py`校验三份原代码执行报告的SHA和客户端版本，检查90个键、display→Model、两阶段职业映射、九组身体复用，再生成统一配方及统计。配方保存在忽略目录，不上传完整原表。

共用构造顺序为：原阶段与相机 → 原display/身体 → 原服装槽 → 材质与纹理 → 按实际模型类型挂接 → 动作控制。骨骼蒙皮、无蒙皮的装备、武器祖先节点和附加效果分别是需要核对的类型差异，不能凭文件名或长度猜。多资源包同名文件仍按原挂载/查找顺序取证，不能默认最新补丁。

冻结早期职业资源清单解析出8类效果文件；其中14行有多包候选，13行尚无已解析材质。这是早期清单的取证状态，不等于13份资源不存在，也不代表候选已全部确定。统一几何/材质类型扫描应保留这些差别。
