# 新手神殿：从截图具体位置核对原模型

本轮只查出生区域周围的悬空、开口，没有补面、加底板、调整用户角色位置、改变光照或发布新地图。旧位置复现只布置在全新隔离卷的验收角色上，未读取用户存档作为测试输入。当前新角色采用的 `cinematic7` 是用户授权的试玩落点，仍不是已确认的原版首次出生点。

已有的整窗模型组合、包围盒核查见 [神殿组合与楼层](TEMPLE_ASSEMBLY_AND_LAYERS.md)。本轮新增的是**原三角形 → 网页实际部件和同镜头射线**的对应，不把整盒相等当成每块面都正确。

## 当前可以确认的部分

主任务使用隔离测试角色拍摄了两个位置，用户存档不变：

- 当前新角色落点 `(-2594,135.729996,-64)`：外庭和神殿台阶显示完整。原 `god_temple01` 的16个部件、`god_temple01_inside01` 的21个部件，均实际进入主相机提交。

## 同镜头具体检查

### 当前试玩落点

有效门口镜头为1280×720。主任务的实际网页 CPU 射线与本工具从原三角形计算的7条射线中，6条命中同一原三角形、部件和材质，1条双方均为空。世界命中坐标最大差 `3.62e-8`；实际 per-mesh 世界矩阵与原摆放、原节点组成的矩阵差为0。

额外标记点对到了原模型的门柱和台阶。例如下台阶像素 `(640,320)` 对到 `god_temple01` 第13部件、第4725个三角形；上台阶边缘 `(620,205)` 对到同部件第4745个三角形。编号从0开始。这些部件实际进入了网页主相机提交，并没有被 drawRange 或错误分组裁掉。

### 旧位置的大片开口

有效旧镜头为473×849，截图与读取的相机、视口尺寸已经核对一致。

- 开口中心 `(230,165)` 对本批七模型没有原三角形命中；最终网页观察器同时检查了所有当前 resident 静态网格，这里也没有几何命中。这个结果仍不能证明整个原活动场景没有其它模型。
- 屋檐边缘 `(230,95)` 对到 `god_temple02` 第3部件、第1373个三角形；`(310,115)` 对到同部件第1412个三角形，世界高度分别约151.5613、150.8096。原索引有这两块面，网页该模型全部10个部件也实际提交了；没有发现网页漏掉这两块面。
- 远小柱 `(80,320)` 和边缘 `(30,340)` 对到的是 `god_bridge_04`，不是 `god_temple03/04`。原摆放 ID 为274022992，原位置为 `(-2531.261475,132.349991,205.651215)`，单位旋转、缩放；分别命中原三角形360、436。最终全部静态网格的网页 CPU 射线也命中这两个原三角形；该部件实际提交1次，实际矩阵差0。它本身就是独立的原几何组合，不能按截图观感补墙或支撑。

第一份旧位置宽屏 JSON 与后续窄屏截图不对应，已明确拒绝用于逐像素结论。不能把不同镜头的空射线冒充截图的缺面证据。

最终有效旧记录为主任务私有目录的 `old-bridge-allstatic.json/.jpg`，使用相机读回和截图尺寸一致的473×849；本工具重新计算了其中12条实际采样。此前失配数据保留为被拒绝的研究记录，不用于结论。

### 实际行走与保全

Linux隔离卷中保留旧位置验收角色，同时从实际选角入口创建第二个验收角色。第二连接按当前默认落点进入庭院，键盘走到入口台阶，世界位置从 `(-2594,135.729996,-64)` 到 `(-2609.409424,138.100723,-64)`，再返回庭院 `(-2586.130371,136.048691,-64)`。两连接的小地图均收到另一玩家，浏览器无warning/error；这是该段庭院与台阶的实际走动检查，不代表完整路线验收。

QA使用当前线上等价私有包和部署代码，只追加私有观察器。与线上交付索引比较，除被观察的入口及新增观察模块之外，其余2723份公开渲染资源、模型和辅助文件的SHA保持。观察器不进入游戏菜单，不修改相机、几何、材质、输入或存档；所有位置夹具都在新的独立测试卷，未访问生产存档盘。用户两份本地存档和两份既有草稿另核SHA保持。

## 原代码和适配边界

原库 SHA256 为 `77f449f2100a4717578e282bb04f1f8fff25d25c7bfa461d7d39ee49d1cb8ca4`。执行了原 BRES 读取/重定位、`0x117c40c` 缓冲前缀准备、`0x112330c/0x111dae0` 节点装配、`0x1362320` 节点刷新；源可见字由原 `0x1362e30` 消费。

旧探针对前缀数量的研究范围为16。室内主体有21个前缀，并非压缩或坏文件。本轮仅在新的子类中把研究输入上限扩展到256，仍执行同一原读取函数并核对返回字节，原文件和旧工具不改。

内存分配、字节流和 mesh 资源存储仍是明确的执行夹具；没有提供原 GPU 成功返回，也没有运行原 Android 客户端。网页的 `onBeforeRender` 只证明当前宿主提交了该部件，CPU 射线只证明选中的原三角形对应；二者都不是原 GPU 像素读回，也不能验证纹理透明裁切后的每个像素。

边界边分析只记录原几何未共享的边，不焊接、不封洞。UV 分离顶点或极小数值差也可能形成边界，不能凭边界数量制造补面。
