# 玩家只读后台与运行故障恢复

后台地址为 `/admin/`，与游戏使用同一服务、域名和存档盘。它是用户要求新增的服务器管理工具，不是原游戏界面；没有放进游戏菜单。范围为在线玩家与已存角色资料，不记录登录历史，不提供修改、删除、移动或发奖励功能。

后台读取当前存档容器和真实在线连接：角色名、ID、职业、等级、累计经验、生命、金币、击杀、房间、当前坐标、背包数量、装备及时间。连接时间在本次真实加入房间时记录，离线角色不猜测最后登录时间。未知字段显示空值；数值属于当前试玩服务，不冒称原服务器成长规则。

后续补充了在线IP、请求头中的浏览器/系统与User-Agent、在线时长、最近通信、现有WebSocket心跳的实际往返、世界/存档坐标和背包明细，并展示在线房间、服务运行时长与进程内存。连接资料只保存在当前会话中，不写角色存档或历史日志；离线/未曾采集的IP、客户端和心跳值保持空白。连接往返不是完整的按键到画面延迟。Railway环境从有效的单一 `X-Real-IP` 读边缘地址；本地环境只读socket地址，不相信任意转发头，依据[官方请求头说明](https://docs.railway.com/networking/public-networking/specs-and-limits)。没有地理位置查询，也不将请求头用作角色认证。

`OC2_ADMIN_PASSWORD_HASH` 使用 `scrypt$盐$摘要` 格式。未配置有效摘要时资料接口关闭；明文密码、摘要、恢复码、角色令牌及完整存档不通过后台返回，不进入 Git。页面使用 HTTPS 下的 HttpOnly / Secure / SameSite=Strict 会话，8小时到期；登录尝试受限，接口不缓存，登录/退出检查同源。`OC2_ADMIN_LOCAL_HTTP=1` 只供隔离本地 HTTP 验收，Railway 不设置它。

## 无法开始的原因

2026-11-14 排查确认：原物理宿主的一次 RPC 超过既有20秒期限。旧网页服务器把运行异常也交给 `storageFailure`，导致后续连接一直收到“存档当前不可用”；健康接口还以HTTP200返回 `ok:false`。当时角色JSON可正常读取，并未发现该文件损坏。

部署适配现在仅对已识别的原物理传输超时或后台退出，区分为运行故障，停止新移动，向玩家报告场景服务正在恢复。已有正常状态经原 `close()` 保存后，进程以失败状态退出，让现有 Railway ON_FAILURE 策略重新启动。真正的存档写入错误保留原保护；关闭时写入失败会明确记录，不能当作保存成功。不放宽原20秒期限，不切换碰撞算法，不改坐标、速度、规则或画面。

存档盘同时留有三代重复素材缓存，已接近满盘。仅移除一份与本地备份SHA完全一致的旧缓存，保留当前使用包及上一份包；未删除角色、角色备份或原素材来源。修复继续使用原 `203eebc9…` 素材包，没有混入地图/任务/人物研究候选。
