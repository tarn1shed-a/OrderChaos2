同日后续：[新手区域分阶段加载](STAGED_LOADING.md)。下文是上一轮完整准备版本的验收；后续在严格校验的独立入口副本中调整加载顺序，原私有源码文件仍保持，浏览器入口存在明确适配。

2026-11-13。本轮只改部署层，127 份已核对游戏运行文本、52 份原指令 Python 宿主、原素材及私有资料包 SHA 保持不变。没有改角色、碰撞、光照、地图、界面布局或进入条件。自动任务 2 保持暂停。

## 为什么原来等待很久

旧历史预览直接串行请求大量模型 JSON 和小图片；公网每次往返都会累积等待。大 JSON 没有 HTTP 压缩，重复进入还缺少可复用的素材缓存。页面已打开、服务器健康，不等于浏览器已经拿到绘制所需的文件。

一般网页游戏会区分入口必需内容和后台内容、并行下载并保留缓存；例如 [PlayCanvas 官方加载说明](https://developer.playcanvas.com/user-manual/optimization/load-time/)。本轮保留原预览的加载与绘制代码，用独立传输层减少它的等待；没有假称恢复了原手游的完整流式加载调度，也没有提前解除资源就绪条件。

## 实现边界

- `deploy/prepare_delivery.mjs`：从已经校验的私有包清单建立公开文件白名单，启动游戏前生成 Brotli/gzip 无损副本。PNG、字体保留原文件。原文件只读，压缩副本在容器临时目录，不占角色磁盘。
- `deploy/static_delivery.mjs`：只接管白名单静态 GET/HEAD，协商压缩、ETag/304，并仅将 HTML 的外部游戏脚本入口接到传输引导。游戏 JS 字节和界面节点/样式不改；WebSocket、存档、原生输入和其他请求不缓存。
- `deploy/delivery_boot.mjs`：注册缓存工作线程并立即导入原游戏入口，后台预取继续执行。未支持或启用失败时回到原入口，HTTP 压缩仍可用。没有新增可见界面。
- `deploy/delivery_worker.mjs`：从真实入口和资源引用生成的依赖清单中，最多 12 路并行取文件；以解压后的 SHA256、字节数和类型核验后存到浏览器 CacheStorage。相同内容复用、更新按哈希区分，页面绑定版本可在工作线程重启后恢复。索引不可用或缓存额度不足有回退；内容校验不符则拒绝使用，不把错误文件放进缓存。
- `deploy/delivery_audit.mjs`：重读全部公开原文件及每份压缩副本，流式解压后核对内容 SHA。该工具不是游戏机制。

未版本化的 HTTP 路径必须重新验证，避免新部署沿用旧文件。浏览器内部缓存按内容身份取用。浏览器可能清理缓存，换浏览器/无痕模式仍需首次下载；这不涉及角色存档。

## 本地 Linux 验证

同一份私有包、同一地图、同一浏览器环境；分别给旧版和新版每个请求增加 **80ms 延迟**，没有限带宽。时间从导航到原“进入试炼”按钮解除禁用，字节是该段请求的响应体传输量，不含 HTTP/TLS 头。

| 场景 | 就绪时间 | 响应体传输量 | 请求数 |
|---|---:|---:|---:|
| 旧版冷加载 | 72.07 秒 | 141,495,542 字节 | 1134 |
| 新版冷加载 | 16.45 秒 | 65,202,100 字节 | 1071 |
| 新版刷新 | 2.24 秒 | 179,512 字节 | 15 |

这是受控延迟下的本地对照，不能承诺每个玩家公网都是这些秒数。全公开清单 2536 文件共 330,903,891 字节，允许 Brotli 时合计 125,895,288 字节；这个总量覆盖更多文件，不能与首屏实测下载量混为一谈。251 地块、1219 光照图实例、121 图集、401 普通材质、30 裁切材质的页面核对结果与旧版相同，截图对照一致。

18 项传输/工作线程测试通过，覆盖无损字节、协商/HEAD/304、相同内容并发、版本切换、工作线程重启、校验失败、缓存禁用、索引回退和私有路径隔离。2536 个原文件与 880 份独立压缩副本全量 SHA 核对通过。8 项部署边界检查和 127 运行文本身份检查通过。独立 Linux 存档中的双连接、原碰撞移动和装备广播通过；重建容器后位置、装备、物品与角色保持。没有用测试替换游戏逻辑。

最初验收发现侧效应 import 未计入依赖、刷新并发重复读取索引，修正传输层后重测。旧失败记录仍保留，没有隐藏为成功。`tools/delivery_benchmark_proxy.mjs` 仅限回环诊断，其计时观察代码不进生产页面。
