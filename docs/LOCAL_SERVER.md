# 首次安装与迁移到另一台 Mac

## 安装与启动

1. 安装适合这台 Mac 芯片架构的 Node.js 22.13+ 和 pnpm 11.25.0。
2. 克隆代码后，进入仓库根目录。
3. 安装依赖：

   ```sh
   cd prototype
   pnpm install --frozen-lockfile
   pnpm start
   ```

4. 打开 `http://localhost:8787`；使用不同名字、相同房间号测试双人移动。

之后可以双击根目录的 `start.command`。首次运行仍需先安装依赖。`NODE_BIN` 环境变量可指定 Node 可执行文件；默认使用 PATH 中的 Node。本机 Codex 的用户目录 runtime 仅为可选回退，不会复制到朋友的电脑。

若需要配置端口，将根目录 `.env.example` 复制为 `.env`，修改 `HOST` / `PORT` 后重启。两种标准启动方式都会读取根目录 `.env`。只运行 `node prototype/server.mjs` 时，需要自行通过 shell 设置环境变量。

## 资源单独传输

GitHub 仓库不含任何游戏资源。二维营地无需资源即可使用；三维实验场需要额外准备转换产物。

最小三维运行文件：将开发机的整个 `game-data/converted/` 文件夹复制到目标机器同一路径，保留子目录和文件名：

```text
仓库根目录/
├── prototype/
└── game-data/
    └── converted/
        ├── manifest.json
        ├── maps/
        ├── models/
        ├── effects/
        ├── rendering/
        ├── ui/
        ├── library/
        └── textures/
```

资源到位后打开 `http://localhost:8787/explore.html`。不需要把 APK、原始 960 MiB 数据包、解包目录或逆向环境传到服务器，仅运行网页所需的转换产物约 30 MB（含完整中文字体，随转换内容变化）。

如需在目标机器重新研究或转换，才需要另传原始导出目录 `game-data/com.gameloft.android.ANMP.GloftO2HM/files/`，并安装 Python 3.12、创建 `.venv`、安装 `tools/requirements-resources.txt` 后运行 `tools/build_resource_preview.py`。

开发机还可运行 `python3 tools/art_library.py export`，将完整转换资源整理为独立 ZIP，默认保存在 `game-data/transfers/`。目标机拉取相同版本代码、停止服务后，运行 `python3 tools/art_library.py verify /path/to/oc2-assets.zip`，再运行 `python3 tools/art_library.py import /path/to/oc2-assets.zip`。该工具仅需 Python 标准库；实际文件名以导出结果为准。校验失败不会替换现有资源；成功时旧 `converted/` 自动留为同目录下的 `converted.backup-…`，不会读写角色存档。完成后重新启动服务、刷新浏览器。

素材库入口为 `http://localhost:8787/assets/library/index.html`，也可从三维页“资源与玩法”打开。分类目录含原图、字体示例、资源用途/来源、像素尺寸与校验信息，方便另一个网页项目按相对路径复用。不要只拷某几个图标或字体文件；整套 ZIP 与代码匹配后再更新正式服。

## 朋友连接服务器

同一局域网：朋友使用服务器 Mac 的局域网 IP，例如 `http://192.168.1.20:8787`。不要发送 `localhost`。默认监听 `0.0.0.0`，主机需要允许该端口的本地网络访问。

不同网络：需要另行设置虚拟局域网、穿透或公网部署；本项目尚未配置这些服务。服务器运行期间保持 Mac 开机、服务不退出并避免休眠。

## 更新与数据

更新时先停止服务，拉取匹配版本的代码、更新依赖，并另行同步对应版本的 `converted/`，然后启动。不要同步正在变化的整个工作目录，也不要复制 `node_modules/` 或 `.venv/`；Intel 与 Apple Silicon 机器应各自安装依赖。

技能及换装版本需要匹配的 `converted/models/elf-female.json`、`wolf.json`、`effects/combat.json`、角色/装备贴图与 `manifest.json`，请整体复制本次构建的 `converted/`。旧 `forest-elf.json` 只保留为研究参考，不能代替新玩家基体。只有旧资源时页面会明确要求重建；开发机执行 `.venv/bin/python tools/build_resource_preview.py` 后把产物单独传给正式服。本轮代码会将旧角色存档安全升级到v5，原装备、外观、奖励和技能栏保留，旧角色职业设为当前法师原型（2），新增法杖和大剑各一件；更新后刷新页面。待结算施法、技能冷却和怪物减速仍为会话/房间状态。

当前要求 `oc2-combat-effects-v3` 与 `oc2-original-ui-v10` 与 `oc2-native-gameplay-v1`（`converted/gameplay/native.json`），玩家模型内含 `oc2-equipment-appearance-v1`、`oc2-character-hair-v1` 与 `oc2-character-materials-v1`。整包包括原LUT、各界面清单与图标（含手机摇杆/小地图边框、技能面板及法师资料）、81张场景/特效/角色贴图、4个WOFF，请完整同步 `converted/`。原材质库、源表和松散TTF只由开发机转换时读取；运行机器只需转换产物，无须BDAE、SWF、APK或反汇编。角色头像和装备全身预览随穿脱渲染并缓存，无需另传截图。未覆盖的稀有字仍回退系统字体。

角色存档当前为 **version 5**，新增职业字段和两件练习武器。读取v1/v2/v3/v4时先验证全文件；首次落盘前，在同一个runtime目录保留精确原字节的characters.json.vN-backup-….json，再原子写入v5。旧角色明确迁入法师原型（2），只补发一次新增法杖/大剑；旧奖励、生命、装备、外观、位置、凭据哈希与已有技能栏不变。尚无服务器技能栏的旧版本继续执行原一次性导入。坏存档拒绝启动并保留原文件，不使用旧版程序打开v5。回退需停服，同时恢复旧代码与对应旧版本备份。

新建三维角色可选择职业；恢复已有角色时以服务器职业为准，不能靠新建菜单改职业。原版表约束当前法杖仅法师/武僧、大剑仅战士/血骑士。旧单手剑保留外观，但未找到普通攻击库入口，三维页提示卸下或换武器；不会将旧剑错误套用双剑技能。跳跃、连击进度和当前选招为临时状态，重连从地面及首段普攻开始。完整职业技能体系、原伤害/射程/冷却与原碰撞仍未恢复。

三维页按B / C或“背包与装备”打开，查看时停止自己的移动输入，世界仍继续运行。物品筛选、五件装备穿脱、三款发型、六组发色和五组肤色可用，外观先预览再保存。服务器拒绝倒地或施法时的修改；保存后头像、世界和同行者同步更新，不改变装备或战斗属性。当前仅有精灵女性角色。原法线/高光/染色材质接入，覆盖身体部位、剑对齐和全局光照为网页适配；色板两值的选值与RGB24解码仍是网页约定，未证明原生字节顺序。

三维画面铺满窗口，说明面板默认关闭，按H或右上“营地”展开，Esc收起；背包使用B / C或右上按钮。打开面板会清空自己的移动输入，世界继续运行。首次进入与离开后使用独立的名字/营地弹窗，不需要展开说明面板。

当前按原手机弧形HUD显示右下普攻、四个技能槽和跳跃，左上状态环内为实时小地图；左下浮动摇杆空闲时隐藏。保留WASD / 方向键、右键镜头、滚轮缩放。原先十格逻辑布局和自定义键位仍保留，右上“键位”可修改按键；固定原手机显示位置下暂不拖拽换位。Esc关闭窗口，设置保存到服务器。

布局和键位配置本身仍为version1，嵌入v5服务器角色存档中，只通过本角色welcome/progress及保存回执返回，不进入房间公开快照。修改即时写盘，成功回执后显示“已保存到服务器”；待确认期间的连续改动会排队保留最后一份，超时显示“重试保存”，断线后未确认的改动不冒称已保存。已有服务器设置始终优先于旧浏览器缓存；一次性旧设置导入请求不会覆盖服务器已有值。刷新、重连、服务器重启或换设备恢复同一角色后均载入服务器配置。

本轮需要同时更新前后端代码和UI v10完整资源包。务必整体同步包含gameplay/native.json的新converted，再启动服务器并刷新页面。仅git pull不足以获得原版资源。

当前角色进度保存在根目录 `runtime/characters.json`，始终不进 Git。奖励立即保存，移动定期保存，离开和正常关闭服务会保存最新状态。异常强制断电时，尚未落盘的短时间移动可能丢失；正常关闭请使用 Control-C。

服务器使用单进程原子 JSON 存档，适合当前少量朋友测试；同一份文件只给一个服务实例使用，不要让两台机器同时写共享存档。文件损坏时启动会报错并保留原文件，不会自动清空进度。

备份时先正常停止服务，然后复制整个 `runtime/` 到单独备份位置。迁到 Mac Pro 时可在新服务未启动前复制 `runtime/`，更新代码时保留它，避免用开发测试存档覆盖已有进度。

浏览器仍保存角色ID与恢复凭据，同一浏览器访问同一服务器网址可通过原角色名选择本机凭据。换浏览器、电脑或服务器地址时，在原设备三维页“营地 → 换设备继续这个角色”复制角色恢复码（也可显示后手动复制），退出原窗口；在新设备进入窗口展开“已有角色？使用恢复码继续”，粘贴后点击“使用恢复码进入”。服务器验证后恢复角色与技能栏，并在新浏览器记住凭据。仅填同名会创建新角色；同一角色只能一个窗口在线。恢复码可登录角色，请自行保管，不随邀请链接或Git发送。当前仍无账号密码系统。

恢复码沿用原服务器发放的ID/令牌，不会在新机器上凭空生成角色进度。目标网址必须指向同一服务器，或事先迁入匹配的runtime存档；只拉取Git代码或传素材包无法恢复另一份独立数据库中的角色。

`SAVE_FILE` 可在根目录 `.env` 中另设路径；相对路径以仓库根目录为基准。请放在 Git 忽略的目录或仓库外，不要放进 `prototype/public/` 或 `game-data/converted/`；服务端也会拒绝这两个静态目录。

测试调用 `createGameServer()` 默认使用内存；持久化集成测试使用独立临时目录，不会读取或修改真实 `runtime/`。
