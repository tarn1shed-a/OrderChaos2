## 原依据

- 输入仍为原 APK、ARM64 so 和用户提供的原资源。SHA沿用[原始地图加载](ORIGINAL_MAP_LOADING.md)。所有新文件经原归档长度/CRC与SHA核对，完整数据留在本地。
- 世界 `tutorial.wld` 的原配置及 `a61bdc/a612b4` 确定64单位区块跨度。执行既有原指令探针 `35b204`，原 APK Default 的 `TerrainTileSight=2` 给出中心优先的25个请求偏移。本轮中心明确取历史研究点 `(-42,3)`，对应X=-44..-40、Z=1..5；不是原出生点或已经观察到的最终驻留集，也没有据此写一个新流加载器。
- 地形来自这25个原ATIL文件。每块65×65个原高程、法线字节和RGB565颜色独立保存，不把相邻块的边界合并成一个覆盖写入的共享网格。逐项重读比较通过。高程送显示器时按原float32的0.01倍换算。
- 模型来自原AITM v5记录，217条均为类型2。原实例ID、模型名称、所属地块、平移、四元数与缩放原样保留；经过既有原配置/准入探针，Default槽0的217条均通过创建前检查。这不是原版最终可见数量。
- 33份BDAE逐一读取原顶点、法线、UV、索引、分组及几何节点关联。所有导出核心流和节点矩阵再次与原文件解析结果比较；显示器直接保留原矩阵，不再拆成另一组位置/旋转/缩放后重组。文件读取器仍为独立编写的解析器，不是取得原引擎源码。
- 有对应同名基础PHY的33种模型都能按已核对格式读取。这里只记录可用文件、形状数量和SHA，没有将同名文件当作已确认的活动碰撞分支；原 `_s`/`inside` 选择、注册和角色接触求解仍需继续核对。

## 接入时修正的限制

旧显示器仅接受顶点全白且底层纹理存在的地形。新范围中有64个不同的原RGB565值，以及48个经过原遮罩裁剪后不再保留底层纹理的区块；直接沿用旧限制无法完整接入。

依据原 `TerrainVP.glsl` 的 `COLOR0` 乘法和 `TerrainFP.glsl` 的 `TEXTURE_LAYER_MASK` 分支，恢复原颜色字节，并让第一个仍存在的纹理层直接赋色，后续层按原通道混合。不是绘制新遮罩、手调颜色或改变环境增益。原两份着色文件SHA再次核对，通过既有原读取/格式指纹核查。

边界盘点发现626次重叠法线样本不同、两处重叠高程不同（原整数相差12和-3，即0.12和-0.03单位）。本轮保留每一块的原数据，没有平均或“修平”原文件。原版LOD、索引接边与完整网格调度没有因此完成，不能声称接缝已达到像素级1:1。

原模型纹理和已验证的槽0光照绑定按实例ID继续使用；全局光源、天气、HDR、曝光均未调整。上一轮413份旧素材逐文件SHA核对零变化，旧入口没有被覆盖。

- 新页扩展的是周围原几何展示。演示角色、存档坐标和旧九块测试范围的移动/碰撞保持；没有放大、重映射已有角色坐标，也没有宣称25块范围全部可玩。原相机仍未恢复，镜头可能穿过或被原建筑挡住，未移动建筑来迎合镜头。
