# 玩家种族与原动作队列的接线

本批完成了**人类男、人类女、精灵男各自动作时钟的原 CPU 联合验证**。还没有开放新的正式可玩种族、修改创角或存档，也没有更新 Railway。独立身体预览与“可以正常战斗、换装、存档的角色”不是同一完成标准。

当前生产入口的限制是真实存在的：`deploy/entry_manage.mjs` 只接受 UI 种族 2、性别 1，旧地图 `syncAvatars` 为所有演员创建同一个精灵女工厂。只撤掉创建限制，会产生种族选择与实际身体不符、装备部件不符，以及动作时长串用。因此本批先闭合原队列到不同原骨架的接口，没有把不完整角色直接开放给玩家。

## 原文件给出的差异

原 ARM64 SHA256 为 `77f449f2100a4717578e282bb04f1f8fff25d25c7bfa461d7d39ee49d1cb8ca4`。身体选择沿此前真实执行的 `0x900234 → 0x9d4c48` 玩家刷新；本批重新核对 `creaturemodeldata.tbl` 的模型、Flags，以及每个模型自己 `anim/animations.bdae` 的原片段范围。不是取相近编号或复用精灵女性时长。

| 模型 | 内部 avatar 种族 / 性别 | 原 `run_idle` 范围（毫秒） | 时长 |
| --- | --- | --- | --- |
| 人类男性 Model 1 | 0 / 0 | 727000–727933 | 933 ms |
| 人类女性 Model 32 | 0 / 1 | 694000–694933 | 933 ms |
| 精灵男性 Model 33 | 1 / 0 | 664167–664800；原点 664000 | 633 ms |
| 现有精灵女性对照 | 保留旧接线 | 旧文件/旧原队列保持 | 1166 ms |

UI 的精灵编号为 2，内部 avatar 编号为 1，不能直接把 UI 数字写入模型路由。各候选的脸、头发、颜色和空装备仍是明确输入夹具，不代表原服默认出生外观。

三份模型原表的 Flags 均为 4；执行原 `0x9e96e8..0x9e9704` 和 `0x9e9798..0x9e97b0` 后，得到原动画引擎 flags 3、两个通道。原动作表/状态消费者仍使用已核对的 `0xa4adb0 / 0xa3cf28 / 0xa52ec0`，本批没有重写它们。

## 新接口负责什么

- `tools/species_world_profiles.py` 从三个已冻结的最终 world 候选核对原模型表、动画文件、片段名、范围和原时钟描述，产出有 SHA256 的加载输入。原文件和完整表不进入 Git。
- `tools/source_species_queue.py` 继承现有原 CPU 队列，只在明确绑定的演员一次同步 tick 内供应该模型自己的已加载片段视图，结束或失败后恢复共享上下文。未绑定的旧演员保持原路径，不默认分配种族，也不重解释已有队列。
- `tools/preview/species_world_motion.mjs` 消费原 CPU 输出的 current/previous、原权重、循环位、ageMs 和两层一致性。模型/范围不符、未知片段或两层不一致会拒绝；缺输入不补待机、插值或新状态机。原 f32 权重残差保留，不另做归一化。

动作请求、两个队列、优先级、时间推进、完成位和回调仍执行原指令，包括 `0xa4d6c8 / 0x331a28 / 0x331cf8 / 0x330d0c / 0x1196824 / 0x11962c0 / 0x32b210 / 0x32b24c`。模型/GPU 载入完成没有伪造；这里供应的仍是明确的已加载标量轨道视图。

浏览器继续调用此前独立核对的最终原关键帧采样器（本地交接 `docs/CHARACTER_WORLD_MOTION.md`）。JSON 换成新模型而仍使用普通 Three 插值，不能视为恢复。

`sourceMotion.sha256` 是本地已核资料的版本对应，不是原网络协议，也不认证消息来源。将来正式接线仍必须由服务器持有的角色模型/外观状态供给；不能信任玩家自行提交的模型编号或来源字符串。

## 本地核查结果

原 CPU 中交错运行人类男、人类女、精灵男、旧精灵女四个独立演员，各 107 tick，共 428 tick。输入为同一明确地形点、相同水平输入和 50 ms 宿主节拍，经历跑动、停步、再移动和再次停步。

- 人类男女在停步记录索引 19 转入 idle；精灵男为 13；旧精灵女仍为 24。切换前原时钟分别精确停在 933、633、1166 ms，完成计数各为 1。
- 四个演员最终位置完全相同，原物理和水平输入不因模型时钟改变；按模型运行后，共享旧 profile 身份恢复，异常路径也恢复。
- 当前世界工厂的三个实际骨架重放全部对应原记录，共 321 姿态；独立第二实例不受影响，错误模型包在改变绑定前拒绝。
- Python 5 项、Node 3 项通过。无私有资料时分别为 1 通过/4 明确跳过、1 通过/2 明确跳过，不把公开 CI 跳过算作原资源验证。
- 实际浏览器查看三套身体同时停步与再移动：41 次绘制、4607 三角形，零 warning/error。画面为已有独立审阅材质与固定相机；不是正式地图、原环境光或正式游戏新增界面。临时只读服务验收后停止，没有启动 Docker。

完整记录、三份原模型加载输入、真实截图和收据留在忽略目录 `analysis/raw/species-world-router-20261115/`。两份用户草稿和两份本地角色文件 SHA256 保持，未访问或改写生产存档。

## 正式开放仍需完成

1. 在创角、角色持久化、房间快照和头像/属性预览之间保留明确种族、性别及外观；不能把旧角色当人类默认，也不能借用创角展示服当初始装备。
2. 接回每种身体自己的普攻、受击、死亡、武器与施法动作，以及原部件遮挡和装备。当前基础 world 候选不覆盖这些，不能仅撤掉创建限制。
3. 原跳跃/空中优先级与不同姿态合成仍按既有证据边界处理，本接口不以跑步片段填补缺失动作。
4. 正式地图中的联机、换装、停步/跳游/战斗、刷新恢复及存档保全通过后，才发布相应可玩种族。本批没有把独立联合验收称为正式入图或上线。

地图与 NPC 专线继续；原 NPC 活动 GUID、出现政策和任务批准依旧缺原服来源，保持用户要求的纯原版取证，不补规则。本批未恢复或修改旧自动续跑任务 2。
