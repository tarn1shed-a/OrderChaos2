# InitialFeed 解密 key 来源补件

`250bef0` 的 16 字节**已经保存在原 so 的 `.data` 文件内容里**，不是尚未下载的空值，也不是必须由外服提供的字段。目前没有证据支持把上批解码失败归因于“缺外部会话密钥”或“必须先跑全部初始化”。这不表示已解开 `InitialFeed.dat`。

本补件不改此前冻结的 73 个文件，只新增 `tools/tutorial_script_initialfeed_key_probe.py`。记录在忽略目录 `analysis/raw/tutorial-script-initialfeed-key-20261115/`，不输出 key 原值。

已核实的范围：

- 原 ELF 的该初值为文件支持的 `SHT_PROGBITS/.data`，16 B 的 SHA256 为 `7757fe462cc33e43218e57f833f67e7daddb73aa281d1e3ac3a6af854beb0096`。该节可写，不能称它是只读内存。
- `.rela.dyn` 没有写入该范围的重定位，也没有以该范围为 addend 的指针别名。原符号表中没有覆盖它的具名对象。所有文件支持节的绝对 32/64 位地址字节检索也未得到指向该范围的地址。
- 对原 `.text` 的 28,641,180 B 做 ADR/ADRP 与后续最多 16 条指令的局部地址传播，共核 83,826 个候选窗口。只解析到 `ecbdc0` 和 `ecc03c` 形成该地址，分别位于 `ecbd54` 解密包络和 `ecbf58` 加密包络，传入 `X4`；未识别具体赋值初始化器或原直接写者。
- 原 `.init_array` 有 487 项；上述两个消费者都不是其直接入口。完整列表已固定在私有记录中，没有把这项检查冒充所有初始化后代都已执行。
- 在原加密器 `18d4f84` 和完整原解码器 `ecbd54 → 18d5140` 的合法测试包络上，记录到 260 次来自原指令的 key 读取，0 次写入；前后与 ELF 初值逐字节相同，包络返回 `0`，正文与明确的测试输入一致。字符串存储和分配仍是具名宿主接口，没有运行完整应用。

边界：局部地址传播没有穷尽任意间接、容器相对、运行期指针计算或其他模块写入，不能由“未找到”证明该地址永远不变。本批也没有找到可指定执行的真实 key 初始化器，因此没有凭空执行其他初始化或另试 key。

准确交接应是：**原静态初值已有并已使用；尚无真实改写证据；不能声称另一把运行期或外部 key 是必需条件。** 上批有原依据的两种头变换仍都未通过文件长度校验，实际活动文件流与选择输入仍未闭合，`InitialFeed.dat` 的正文和用途继续保持未知。
