## 原流程

不能只按一个按钮或一个方法推断可见动作。原 Race/Class 的 onShow 都先 onCreate/Init，设置选择回调后 Selected 会调用绑定，随后才 EnterPanel。Class.Init 真正换职时可能条件请求 show，但随后的 EnterPanel1 经53d3e8/53ca0c重新创建人物，先前尚未选中的 show 留在退休人物里；最终人物从 generic idle 开始。实际职业按钮点击后没有这次 EnterPanel，才保留自己的 show→idle/idle02 队列。相同职业的538b74直接返回。

原 Character_Race 绑定将 game 职业序号清为0，同种族/同性别输入也会清；同身体的538b74仍保留 owner 的职业和动画历史。Race页 Init 本身也调用此绑定。因此返回种族页后下一职业页恢复第一职业，不能沿用网页上一次的职业序号。

owner 构造先清零，随后按原模式从 game 恢复；不把零称为原版所有会话的首次职业。网页新草稿继续使用现有明确的0初值作为适配输入。完整原入口证据在本地 `creation-initial-all-20261116/entry-native-v1`，历史选择回调证据在同目录 `history-native-v1`；不是原AVM/Android会话执行。

## 承载与边界

43份完整自身 Class 三段队列复用同一原取样、时钟、两通道选择和150ms混合核心。84份 shared geometry 和四份旧 Class 演员使用同一个姿势验证/赋值函数；薄 writer 在接管前停止有限 mixer。Part 的45份自身有限 idle 继续独立，不挂 Class 回调。原图形、布局、材质取值和角色准入不因此改变。

真正职业事件、事件前 owner、当前异步代次和精确自身 display 构建共同决定网页承载。宿主构建完成只作为明确的网页条件输入，不称为原53d3e8缓存或Android GPU就绪。退休请求不得作用到新人物；相同职业不重建或重播。旧不可变素材和契约保持，新能力只通过新 profile 激活。

原种族页 generic/show 的选择回调尚未接通，不能从加载完成或用户点击补 counter。进入 Race 后保守保留未知历史；Class 初始续播只接受完整已知历史和自身范围，否则继续现有有限 idle。真正自身 Class show 首次选择时会在读取旧历史前覆写 counter/selected；网页使用不对外暴露种子的受控分支，在实际当前演员帧选择后才记录新的已知历史。

后台标签页恢复属于网页呈现时钟适配：隐藏时暂停预览，恢复以明确零毫秒帧继续，不制造中间原帧，不修改世界时钟。长期菜单不保留研究日志，审计模式另用于原边界对照。
