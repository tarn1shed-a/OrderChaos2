研究工具中也删除了无原运行状态依据的部分：试验门摆放/轨迹导出、固定slot0/config0/mode0光照配置及地表运行配置导出、预览归一化UV/地形拼装输出，以及自写导航门户图。保留只读字段解析、原生指令检查和有明确边界的研究工具；这些工具仍由本项目编写，不能称为原游戏源码。

## 文件如何被找到

0x8fcb1c从世界文件名派生普通包、layer包及10至15号更新包的请求。原字串包括 `_layer.bin`、`_layer2g.bin`、`_upd%d.bin`、`_layer_upd%d.bin`；layer两种名称由原全局分支选择，当前设备值未知。

0x8fb9f8在锁保护下分两组查找：本轮这些调用的w2=0分支，按对象+0x208、+0x200…+0x1e0，再+0x1d0顺序请求；另一分支使用+0x230…+0x210、+0x1d8。已打开的更新包先尝试，未找到再退到相应基础包，最后还有全局文件入口0xa7e490。

这比“随便从一个包拿同名文件”更具体，但不是全部DLC优先级都已恢复：包管理器0x8f6f80、所有缺包处理、动态下载及运行时选择仍未完整核对。本轮离线核验遇到多候选就报出歧义，不替原程序选择。

## 建筑、碰撞与光照的实际任务顺序

0xa60a60的原跳转表0x1e64430已经逐项核对，顺序不是本项目设计的：

| 原状态 | 入口 | 作用/关联 |
| --- | --- | --- |
| 0 | 0xa60b4c | 拼 `world/<世界>/items/<坐标>.itm`；有phasing和_1f分支；读取AITM。版本5直接采用，旧版本存在转换分支，本轮不支持全部旧版 |
| 1 | 0xa61030 | 按记录模型索引取字符串；经过原过滤后请求碰撞，并使用记录TRS和世界配置计算位置 |
| 2 | 0xa61560 | 请求同区块声音资料；本轮只确认任务入口，没有恢复声音运行时 |
| 3 | 0xa61884 | 在原全局条件允许时加载slot0/1光照资料；不能由本项目擅选当前slot |
| 4 | 0xa6196c | 读取实例与光照记录，经类型分派/过滤后调用对象工厂 |

这是单个建筑区块任务中的次序，不代表整张地图全局串行加载，更不证明当前39个实例在所有质量/phase条件下都显示。

### AITM到可见模型

每条v5记录76字节。+0在0xa61acc之后用于2、8、15、16等类型分派，本批39条均为2；旧读取器把它笼统叫flags，现已改记 `sourceType`。+4是实例ID，+0xc是模型字符串索引；+0x10开始的位置、+0x1c四元数、+0x2c缩放沿原消费路径可核对。+8仍保持原值，未编造含义。

类型2的对象vtable起点0x2424188，+0xb0重定位到0xa63218；后者建立模型对象并尾调用0x33ebf8。原模型slot/config分支继续决定base或_l模型请求，不能只因为base文件完整就说它是当前原设备选择。

另外已确认世界初始化请求 `world/tutorial/bdaeInstanceConfig.xml` 和 `EntityConfig.xml`。原XML含实例ID、level以及模型/实例的culldistance、lodlevel、device、phasing等字段；0x4cb934出现在实例/碰撞过滤路径中。这些不是可以忽略的摆放装饰。XML所有字段的优先级、裁剪行为和实际设备值仍未全部核对。

### 同一实例到PHY碰撞

0xa61030 → 0xa85cb0 → 0xa862a4 → 0xa8674c是一条本轮补齐的原调用链。0xa85cb0去掉输入扩展名、处理_h结尾，并按原分支请求_s.phy或.phy；另有_inside_s.phy/_inside.phy路径。当前活动分支仍未知，不简单写成所有模型必用同名.phy。

0xa8674c读形状数量/类型，进入多面体、盒/圆柱等已核对的读取分支。实例记录提供旋转/非均匀缩放和区块位置，0xa612b4起可看到这些数据被用于碰撞变换。原注册过滤、完整接触/台阶和角色运动求解仍是缺口，本轮没有写替代碰撞器。

### 同一实例到光照图

原0xa61884调用0x328d30，按世界、所属区块、phase和slot请求DAT和图集；0xa6196c按AITM实例ID调用0x3293a8查找记录，以记录+0xc定位图集。模型材质的lightMap与uvTransform消费路径继续见scene_lightmap_binding.py，不由包名或相邻区块猜绑定。

一个原文件关联样例：实例253079520在 `items/-041_0002.itm` 中引用 `god_bridge_step01.bdae`；slot0对应 `lightmap/-41_2.dat` 的同ID记录、图集0，指向 `texture/lightmap/tutorial/lightmap/-41_2.tga`（tutorial_lmap_1.bin）。原 `.phy` 也存在；这证明文件关系，不证明原设备当前选择slot0。

再次核对当前研究区域：slot0有39个ID记录；slot1有38个，另一个所属区块缺表；被引用的 `texture/lightmap/tutorial/lightmap/-41_3_l__1.tga` 缺失。缺图不换成别页、不绘制新图，也不据此反推原活动slot。区域光照仍需同时核对map_id=5的原zones 194、195、196、197、199及其选择/过渡输入。

## 明确留下的缺口

1. 登录/地图ID生产者到世界入口的完整调用链、原出生点与原进程现场。
2. 世界对象到地形/建筑任务的完整创建者、区块驻留窗口、异步更新与卸载顺序；不是由以前3×3预览范围决定。
3. layer/普通包的全部挂载与动态下载路径、实际phase/质量/设备参数及所有失败退回。
4. XML过滤和AITM剩余字段的完整含义、原模型slot选择、光照/天气活动状态。
5. PHY各分支的实际选择、对象注册/生命周期和原角色接触求解。
6. 原天空、最终GPU状态和像素对照；本轮未用网页画面验收代替这些证据。

这些缺口不填默认值，不编造服务端脚本，也不以“本地能运行”关闭。
