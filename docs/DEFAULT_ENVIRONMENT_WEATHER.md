## 核实并修正的预览问题

旧显示器有两个区域选择入口：光照目录含194/195/196/197/199，雾和泛光只有194/195，而且逐帧重选、无匹配时回退194。现改为以已核对的光照选区结果为唯一输入，三者用同一配对和刷新时点；无基区时保留已经建立的值，不制造默认区域。

新增原雾目标核对：`4c6b88..4c6cc0` 中，距离根据 `fog_half>0` 选源行，颜色根据 `fog_color!=0` 独立选源行；半跨度受 `(near+farPlane)/2` 限制，再乘配置系数。直接执行此原指令块、原队列写入函数，只有内存/分配使用合成夹具。APK Default 经原配置覆盖选择得到 `CameraFarPlaneDis=240`、`EnableFogDistanceLimit=false`、`FogDisCoef=1`。5个源区域逐项比较通过，40组边界/回退实验也与原指令一致。区域195仍为 near89/half101，没有凭感觉缩短雾。

范围说明：缺失的196/197/199原子区在当前九块地形以外。本轮修正了目录和保持状态的接线问题，**不能称它是当前新手预览偏暗的主因，也没有实际走进这三个区域做画面验收**。它们只有源目标/指令与公共适配测试。

另发现旧后处理采样只在加载第10帧记录一次。之前报告的 `(33,26,24)`、`(5,5,6)` 及墙面拆分，属于当时固定加载镜头的离屏实验，不能用来代表移动后的当前画面。现改为镜头停稳后重新采样，同时记录镜头矩阵、区域、帧号及 `samplesAreCurrentView`，移动期间不把旧样本标为当前。该修正只影响核查读数。

仍缺：原灰烬/红旋涡的实际挂接与播放；其他潜在RGB写入和既往状态；实际材质变体/阴影及全部采样；同位置原 Android 画面。原相机与移动仍是历史显示器适配，走动时仍可能被建筑挡住。环境模式0也只是此显示器的既有明确输入，模式4的2秒过渡没有因此恢复。不能把这些缺口用增亮、重新设计天空或自动避障填平。
