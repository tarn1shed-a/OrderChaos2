# 点地后反复掉头：网页控制修正

2026-11-13。修正的是早期网页原型的鼠标点地控制，不是恢复原 Android 寻路，也不改原碰撞指令、键盘/摇杆方向、速度、场景几何、材质、光源或存档。

旧网页按最后收到的角色坐标持续朝点击目标发满幅方向，距离小于 2 个逻辑单位才停止。外网回包延迟或成批到达时，连续两次读取可能直接跨过这个小圆，网页随后又朝反方向追同一个点。这能发生在空地，无须存在墙或台阶。

本地独立 Linux 存档、真实浏览器点地，在上下行各加 140ms 延迟且下行按 400ms 成批传递的压力条件下，复现同一个目标约 8 秒的来回追赶。该条件用于暴露缺陷，不冒称当前新加坡实测网络就是这样。未加延迟时同一路径没有复现。

独立部署入口现在记录点击时的出发位置：保留原来的到达半径，也在权威位置已经经过目标所在的垂直平面时终止追赶。这样即使回包跳过到达圆，也不再反复掉头。没有预测位置、瞬移、改变模型或绕过墙。几何拾取仍使用原网页的地形集合；多层建筑点选、障碍寻路和真正原版自动导航并未因此恢复。

相同压力条件的两次实际点地在约 1.3 秒和 1.0 秒结束追赶，没有旧的连续反追。**延迟大的情况下，停止消息仍可能晚到、人物多走一段；本修正不承诺精准停在点击像素，也不等于消除网络延迟。** 保留失败和过冲轨迹，不能把“停止反追”写成所有移动体验问题已解决。
