# 选角地图水域核对：先修复被误当成水面的 192 块干地

当前 25 地形窗口里的旧 `344` 是保守 pending 数，不能当成真实水面数。对这 25 份 selection TRN 执行完整原读取器后，**192 块被原程序判为干地，真实湿区是 152 块**。旧基础候选把 344 块都跳过，导致部分本来有原地形和贴图的地面出现黑洞。

本批独立追加这 192 块原干地，实际近景对照确认缺口被原地表填回。没有新画地板、移动地形、借 tutorial 贴图或改光源。冻结基础与 151 条静态候选不变；152 块湿区、水面及水下地表仍保留待接状态，不用普通干地材质把它们盖住。候选尚未部署。

## 原区块和文件

`tools/selection_scene_water_probe.py` 复用已经核对的 `NativeWater` / `NativeFloor`，实际执行原 ARM64 `0x358e08`。输入始终是 `world/selection/terrain/*.trn`、selection AWLD 的 `(3,3,1)` 配置和冻结窗口 `[-43..-39] × [-4..0]`；没有复制 tutorial 原点、配置、贴图或环境。

原读取器为每个 8×8 区块生成自己的最低点，水位小于等于该最低点时清除 `0x10000` 水面位。对全部 **1600 个区块**，原最低点、标志和湿区水位与原 TRN/高度交叉核对。干地区块的原内部水位可为 `-10000` 哨兵，不能把它错误地要求为原文件的未激活水位。

原水深图、颜色表和水下地表描述生产者也已对 selection 自己的文件实跑：9 份 128×128 A8 深度缓冲；湿块水位、约 0.025 衰减、打包 RGB；以及原两种地块奇偶下的三角树索引。host 只提供字节、内存/标准库与明确的 pow/powf 接口，没有提供假 GPU 成功。

## 原加载/显示门与尚未闭合的部分

原 `0x3758b8` 并非总调用旧水面工具所选的 `0x360b48`。原库初始 `0x2509330` 是 1，会分派到 `0x3624cc`；但地形管理器原 `0x35bb00..0x35bb40` 会根据 driver `+0x1b5` 的 bit5 清除或保留该字节。两种输入的原分派和条件片段均已执行，不能把“库初值 1”当成“原 Android 实际必定走批处理”，也不能为了复用旧桥接直接设为 0。

原 `0x3624cc` 入口先检查 `0x2509342` 和 world `+0x278`。实际初始 showWater 为 1；map7 通过，map43 被排除，showWater=0 也被排除，三个分支均执行验证。通过入口门不等于资源已就绪或真实水面绘制队列已有内容。两条水面实现都选择原效果31的 `default/under_water`，真实 driver 能力、驻留队列和缓冲构造仍要继续核对。

区域 211 自己的 fresh-start 原颜色已重跑并与冻结值逐项一致：`light_waterSurface=[3.375,3.2558825016,3.0794117451]`、`light_water=[1.2750000954,1.2300001383,1.1633332968]`。本批并未激活或重设这些值。湿块 `(-41,-3)/(2,7)` 的 mask 优化把基础层剪掉，只留后面的层；旧 tutorial 水下地表工具的“基础层必须非负”限制不能直接套到这里，这一具体原 layer/mask shader 组合仍待核。

下一步的具体输入是：追 driver `+0x1b5` bit5 的生产者和原批处理缓冲，核水上 default 技术的实际队列及完成条件，再闭合上述一块原层选择。无需用户提供猜测的环境值，也不把缺真实设备观察本身当成永久停止理由。

## 192 块干地的候选接线

`tools/selection_scene_water_candidate.py` 导出 `analysis/raw/selection-scene-water-20261115/v1/`。唯一追加载荷为 `/assets/source-selection-water/overlay.json`；原地形高度/顶点色、mask、层图、地形 lightmap、环境均继续读冻结 selection URL。只选择“旧 pending=true、原最终水面位=false”的区块，不重复原已画干地，不把 152 块湿区偷换成干地。

干地索引使用原 `a8e8c0 → a8f064 → 352ec8` 的 CPU 生成结果，每块 384 索引；是原初始全分辨率，不是动态 LOD 已恢复。浏览器继续使用已核的 selection Terrain/default 干地运算和深度/剔除状态，没有增加灯光或手调配色。

```js
const dry = await createSelectionWaterDryAppend(THREE, overlay, {
  origin, lighting, json, texture,

scene.add(dry.root);
// 卸载时 dry.dispose()。
```

模块为 `tools/preview/selection_scene_water_material.js`，只增加 10 个原地形分区、192 块干地、24576 个三角。接线时仍使用同一原点、区域 211 fresh 环境；不要修改冻结基础的 pending 清单来暗示湿区已完成。

四项源测试通过：原 1600 区块读取/水参数、原入口门与能力条件、追加区块身份、防重复及前 180 个冻结载荷 SHA。Node 构造/原索引/区域 211 输入/状态/卸载通过。随后在独立 GET-only 静态研究页实际 Chrome 验图：原相机组合正常；研究近景显示同位置隐藏时的黑洞，显示后由原地表正确接回，未出现叠面闪烁。console error/warn 为空。卸载后追加根移除，已上传 GPU 几何 81→74、纹理 135→130，无错误。截图与 console 在本批 `browser-qa/`；近景相机仅核查使用。

临时 Chrome 页、8924 端口已关闭；没有 Docker、游戏服务器连接、角色/存档操作或正式部署。地图天空、活动、湿区和真实驻留仍是独立缺口，不能据此说整张地图完成。复用规律是：**必须用原逐 chunk 读取结果决定水面位；整 tile 最低点只能作为保守缺口计数，不能控制最终显示。**
