## 原代码怎样使用它

| 原代码 | 证据 |
| --- | --- |
| 0x4ac6b4，0x4ac72c–0x4ac760 | 在原状态工厂表里登记键 1 → 0x52a448。 |
| 0x52a448，原 vtable 0x24150e0 | 创建过场控制对象；+0x10 是 0x52a508，+0x38 是结束处理 0x52be7c。工厂类型 1、镜头序号 7、地图 ID 7 是不同编号。 |
| 0x52a508 | 从 [camera] 读取 w%dpointcount/point/dir/speed/delay/endpos/endradius/enddir；参数指定镜头序号。 |
| 0x5384c8 | 以逗号切分，再经 atof → float32 读三分量。原 w7enddir 的 P 空格分支把后面当目标点；原数值消费会读 -64a 的数值前缀 -64，未改原字符串。 |
| 0x52b1d4–0x52b230 | 接受非零结束位置，写对象 +0x22c/+0x230/+0x234，置 +0x248。原缺省零向量走跳过分支，不能当 (0,0,0) 出生。 |
| 0x52be7c 的 0x52bf14–0x52c060 | 在结束位置标记有效且主角色存在时，按结束半径取偏移，从配置 Y+5 经原 0xa87750 查支撑，再调用角色原虚 setter +0x68。**因此 endpos 会移动角色，不只是摆镜头。** |
| 0x58b40c → 0x9f35a8 → 0x4a1e84 | 一个输入处理器读取正整数镜头序号，经角色状态机发起过场。原服何时发送 7、消息号与完整派发仍缺，不制造实际收到消息的记录。 |
| 0x539b58 → 0x5a3014；0x59feb4 | 开场播放 OC_A_v02.mp4。其结束分支明确以序号 **8** 调用 0x9f35a8；不能因为镜头 7 有位置，就替换成“开场后出生在 7”。 |

完整相机初始化、插值和所有退出回调没有运行。原默认结束半径为零，所以本轮两个不同显式随机输入都没有改变 X/Z。静态原碰撞容器中，原结束分支最终写入 **(-2594,135.7299957,-64)**；这是原查询在该检查容器内得到的高度，不修改配置中的 136，也不冒称原 Android 活动场景高度。

原首入消息给的未知位置仍会影响镜头 8 的 CURRENT 和后续玩家位置；本轮不能从已经存在的镜头位置反推出唯一初始角色坐标。

- [splash] 的 mapid=7，经原 map_info 对应 world/selection.wld，包含创角/登录展示镜头；这些坐标没有当作新手 map5 入图点。这里只核对数据归属，未继续创角功能。
- OC_A_v02.mp4、OC_B_v02.mp4 本地存在；GS2C_PlayMovie 只有 mov_name/snd_name，0x5a3014 使用影片名和声音名。影片播放接口不是三维出生数据。
- m_tutorial_start、m_tutorial_daemon_intro 经音频调用链确认是音乐标签；早期仅从名字把它们称为“事件模块”不准确，已更正。旧 module_proto 的 42 条记录不能冒充新手任务正文。
- step_camera_skake 原表头 count=0；通用非空 FTABLE 解码器的拒绝保留，未放松断言或编造相机点。
