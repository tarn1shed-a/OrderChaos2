# 原种族页的地形、静态摆放和水面接线

本批把已独立核对的六组资源接到现有原种族页背景：花草、两条瀑布、最后一条草、192 块原干地、152 块水面，以及它们的 152 块水底地表与水边补色。该场景是原 **selection / map7**，不是试玩中的 tutorial / map5，不能拿这个进度称为新手任务路线已全部恢复。

私有底包已有 3124 份载荷、25 块 selection 原 TRN、146 条静态摆放。本批只追加 54 份运行载荷和新的 `source-creation-stage/manifest-v2.json`，旧载荷逐字节保留，总数为 3178。原 127 份运行文本、53 份物理宿主、现有角色存档、试玩世界逻辑和原界面布局不改。新的清单仅在进入原种族页时使用，不改变正式可玩种族范围。

复核修正：v2 是中间记录，正式接线改用追加的 `manifest-v3.json` 和独立 `source-selection-water-floor-groups/overlay.json`，共 3180 份载荷。原 `3563dc` 会取合组代表，再由 `35127c` 复制效果、颜色表和采样字段。之前 3 格水底误用了成员自己的采样字段；现在按原代表复制结果绑定，仍使用同一个已核对的绘制模块。旧 3178 份文件不替换。详见 [原材质复制核对](SELECTION_SCENE_WATER_FLOOR_GROUP_COPY.md)。

这 3 格的几何、水位、颜色表和碰撞没有改变；同机位的三组前后截图像素差为零，因此这里只声明材质来源修正，不声称有可见改善，也不能据此称神殿悬空问题已解决。

## 宿主边界与验收

`deploy/creation_preview.mjs` 只接受六个具名、固定 URL 的 append 接口，全部准备完成后一次挂进原场景；实际构造出的静态摆放和各类地块数量必须与清单一致。旧 v1/v2 保留可重查，存在 v3 时优先使用 v3。v3 还必须具有原组代表复制证明标记，不接受外部资源重定向或缺少任何一组的半成品。

`deploy/creation_plan.mjs` 把这些资源保持为种族页按需请求。首次进入 tutorial 的优先/后台预载仍应为 1089 / 450；不是把整张选角地图加入进图门槛。原 211 fresh 环境、原相机、角色 TRS、原 UI 位置和画面比例保持。

必要检查包括：六组原构造/矩阵/状态/释放检查，清单与旧载荷身份，正式原种族页的男女切换/返回/再次进入及浏览器警告，隔离 Linux 双连接与移动/装备广播、重启恢复；上线后还需核对全部新素材 SHA、相同服务/盘/新加坡和生产存档。最终发布结果记录在本地 `analysis/raw/selection-stage-release-20261115/release-receipt.json`，没有最终收据前不把候选称为线上完成。

仍缺原要求的 005 天空/远山模型，继续保留空缺，不用别的天空或渐变补上。原活动驻留、异步 GPU 完成、动态 LOD、完整水下相机和全部原帧也未证明。正式人类新角色、完整职业技能、原服任务批准和活动 NPC 是独立未完成项；本批不改写这些状态。
