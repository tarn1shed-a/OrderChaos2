# 原旗帜的骨骼变形与默认播放

本轮把2种原旗帜、17条原摆放接回现有新手地图。旗面由原骨骼关键帧和顶点权重带动，使用原模型、贴图、ITM与槽0 DAT。光源、碰撞和界面不改。网页仍有明确的绘制与计时接口，尚不能称原Android现场或像素级1:1。

## 骨骼怎样带动旗面

1. 原`111dae0`建立源骨骼子树。节点的三个名字字段均保留，动画使用`Bone…-node`，蒙皮还会用`Bone1`等别名；不能只保留一个名称。
2. `11985fc`建立调色板提供器；`119c21c`按原骨骼名查节点，取节点世界矩阵地址（节点+0x28），保存9／7个指针。本轮实际执行，16个骨骼全部找到，不走缺骨骼单位矩阵后备。
3. `1198c40`调用`119935c`，生成“骨骼世界矩阵×原逆绑定矩阵”。实际执行矩阵写入；此处没有再乘一次bindShape，也不要求文件静态姿态等于旧角色读取器假定的绑定姿态。
4. 原GLSL蒙皮段和原CPU位置累加例程`119bd7c`都按原权重变形顶点。本轮额外用原CPU例程处理实际源顶点，核对网页输出；不改逆绑定，不归一化原权重。

网页把骨骼矩阵先表示为**源模型坐标**，CPU更新旗面位置，再由现有场景接口应用一次原ITM变换。该坐标分解、顶点上传和每帧刷新包围球是宿主接口。原材质的纹理/光照图绑定继续沿用既有路径；没有另加旗帜阴影或新光源。

## 自动播放和循环依据

- 原地图模型任务构造`33f2fc`写入加载标志0x5c；`33cfe4`把它送给`11236b8`。其中0x40分支创建内嵌动画，并经`1363c30`挂到模型。
- `11267b8 → 1189b78 / 1189914`建立动画库和时钟，默认调用`118a298(0)`选择第0个片段。这两份原文件各只有一个范围。
- 默认工厂`10f78a4 → 1195f3c`把时钟速度设为1、循环字节设为1；`1196824 / 1196570`从实际范围设置起止并回到起点。`118c038`调用时钟更新入口；原模型更新还会把内嵌控制器加入更新容器。不是因为范围名有“AUTO”而猜测循环。
- 实际执行`11962c0`：到4000毫秒仍保留末帧，严格超过末尾才循环；3999→4000→1→2及多周期输入已与网页时钟核对。
- 原`114a61c`读取type1字节帧号，乘原float32常量33.33333206176758，再按原代码取整数毫秒。不能把字节源改读uint16，也不能直接拿“帧号/30秒”的浮点时间代替原整数边界。
- 原`1109aec`取样，并经属性回调更新节点；旋转走`115d0c8 → 11dd664`。后者的近角阈值是原float32(0.05)，用归一化线性插值；其余分支走原球面插值。不能默认采用Three.js的另一套近角阈值。

完整克隆/资源缓存的实例相位、暂停/改速覆盖、Android实际帧起点仍未观测。网页从各实例加载完成时开始自己的时钟，清楚标为`hostClockOrigin=true`；不加随机相位，也不把宿主起点称作原客户端现场。

## 可复用的文件规律

- 先区分ITM对象类型、scene附件类型、controller kind，三者不能混为同一枚举。
- 9／7骨骼各有3类TRS通道，因此文件为27／21条；应先恢复启动兼容表，再核对运行时属性数。
- 同一模型里骨骼名称、显示名和别名各有消费者；先验证名字解析，再验证矩阵，避免“有骨架但没带动旗面”。
- 静态节点姿态不一定是旧角色导入器要求的绑定姿态；以原最终矩阵写入为准，不重写原逆绑定来迁就读取器。
- 时间源的类型、原整数毫秒换算、旋转近角阈值、末帧循环条件应一起核对；“能播放”不足以证明原流程一致。
- 隔离原函数必须检查启动全局指针。基址0模拟里，读到合法内存不代表读到了有效对象。
