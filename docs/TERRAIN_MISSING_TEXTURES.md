## 原代码怎样加载并处理缺图

固定输入仍为用户原APK及原下载包。原ARM64库SHA256为 `77f449f2100a4717578e282bb04f1f8fff25d25c7bfa461d7d39ee49d1cb8ca4`；工具先核对整个原库，再记录所查函数的范围和指纹。GhidraMCP原响应、反编译及指令仅存本地忽略目录。

| 原入口 | 已核对的作用 |
| --- | --- |
| `354de4 → 3563dc` | 读取地形材质记录和累计字符串表；`356898`调用`143f5c4`请求原路径 |
| `143f5c4` | 查缓存和提供器；所查“空缓存、提供器也找不到”分支返回空引用。没有把目录改写成另一个default.tga |
| `3569ec..3569fc → 1445120` | 纹理为空时准备类别0、类型1，转入内置缺图纹理分支 |
| `1445120 → 1444b68` | 从原重定位字符串表构造`glitch.texture-not-found-2d`，查找或创建该内置纹理 |
| `_INIT_375 / 2cf358` | 初始化原颜色表：类别0是RGBA `[255,0,128,255]`；类别1是`[55,215,55,255]`。不能把初始化前的零BSS当成颜色 |
| `1444b68` | 原描述符`[1,22,0,0,1,1,1,0]`，格式22按原格式表是RGBA8；2D分支为1×1，原填充循环复制颜色表字节 |

另一个分支在没有第0纹理层时确实请求 `texture/tiles/textures/default.tga`；本次并未把它混同于“已有纹理名称但找不到文件”的分支。`553fb4`的pureColor纹理也不是本次地形缺图调用。

用Unicorn分别执行原初始化写入、地形参数准备、描述符写入和像素填充的有界原指令，核对停点及输出。没有伪造GPU成功、没有执行完整Android纹理创建；PNG只是对原计算出的四字节做无损封装。原GL上下文、实际缓存、挂载顺序及真实设备上是否成功创建该后备资源尚未观察到，因此这仍是明确输入下的原分支预览。
