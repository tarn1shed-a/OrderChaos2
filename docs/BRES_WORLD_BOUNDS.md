## 从BRES到mesh局部盒

静态调用关系为资源入口0x1181778，经0x117ec68进入流读取0x148daa8；内存读取分支0x117eea8进入0x148debc。本轮执行的是**0x148daa8及其原重定位方法、随后0x117c40c的缓冲准备**；资源入口/VFS和缓存命中没有运行，流接口由精确的inner BRES字节提供。

| 原位置/入口 | 本轮核对到的消费关系 |
| --- | --- |
| BRES头64字节；0x148daa8→0x148debc | 读取指针表、处理字符串与可移除缓冲；指针表指定哪些字段需要重定位，不把每个看起来像偏移的数都加基址 |
| 头+0x10计数、+0x18指针表；主缓冲+0x28 | 前两者用于原指针修复；后者重定位后指向info。不是把上下文ctx+0x28当作info |
| info+0xb4/+0xb8 | 原geometry记录计数/相对表位置；记录步长0x18，其+0x14相对引用到缓冲wrapper |
| wrapper+4 | 原0x117c40c用有符号16位读取前缀项数，每项8字节；本批原文件为1或2 |
| wrapper+8 | 仍是原文件中的64位缓冲偏移，不是应修复成内存指针的字段 |
| wrapper+0x10/+0x14 | 总缓冲字节数/压缩相关字节数；六个源缓冲后者均为0，本轮不外推压缩分支 |
| 0x117c40c | 分别读取前缀和去前缀的body，执行body内部指针修复，缓存结果于wrapper+0x18 |
| mesh构造0x1130fd8中的0x1131ae0–0x1131af8 | 从准备后的body+0x60复制六个32位字到mesh资源+0x68 |
| 0x1132b78→资源virtual+0x60→0x1132470 | 普通mesh节点从上述资源字段取得局部盒 |

源字段的精确关系现在是：

```text
原文件盒字段偏移 = wrapper中的原文件缓冲偏移 + 8×前缀项数 + 0x60
准备后的盒字段   = 原0x117c40c返回的body指针 + 0x60
```

六个模型在两种字符串分支下，准备前后的24字节均逐字节一致。铁匠铺`hum_archi_smithy001_03.bdae`的前缀是2，其余五个是1；不能把所有模型都当成body前只有8字节。没有扫描顶点重新计算盒子替代原字段。

原全局0x25dd608控制字符串处理分支。本轮明确分别提供false和true，两支都执行原读取/修复代码；true所需的字符串池和存储接口有实验适配。它们产生相同的几何、节点与最终盒子，不代表已观测该开关的活动值。

**适配边界：** 0x111b8c4的mesh查找/显卡对象构造被替换为按原geometry名字精确查找的存储适配，向原节点构造器提供mesh资源对象；其+0x68确由上表原复制指令写入。完整顶点/索引、材质、纹理和GPU对象创建没有执行。本轮闭合的是源字段到已准备缓冲、再到局部盒消费者的字节关系，不宣称完整资源系统已运行。

## 节点、矩阵和标志来自哪里

场景装配0x112330c和递归节点装配0x111dae0均执行原指令。Python没有另建替代节点树，也没有把所有源节点旋转合并到几何根节点。

原节点记录步长96字节，已核对的源字段如下。以下偏移均为十六进制，不扩展成尚未查到的原开发命名。

| 源节点字段 | 原消费/结果 |
| --- | --- |
| +0x18平移三字、+0x24四元数四字、+0x34缩放三字 | 0x111dae0调用节点虚方法，落到0x1364014、0x1363f8c、0x1363f18等setter，写运行节点+0xa8/+0xb4/+0xc4 |
| +0x40非零判断 | 调用0x1362e30改变运行flags的bit3；不是直接把源字当整组运行flags |
| +0x44模式字节 | 进入0x13640a4的低三位模式处理，不能解释成世界盒特殊分支bit11 |
| +0x48/+0x4c子节点计数/相对引用 | 原递归装配，经0x1362f6c及继承更新0x1399ce4形成实际层级 |
| +0x50/+0x54附着记录计数/相对引用 | 本批包括geometry类型3，部分还有ambient light类型4；按原装配分支处理 |

项目工厂vptr0x2416430与引擎工厂0x244d308的本批空间节点槽位分别核对：+0x118→0x112b268、+0x140→0x112b518、+0x148→0x112b460、+0x158→0x112b640、+0x170→0x112ba70。两种工厂都单独执行，不据此选定原进程活动工厂。

矩阵与flags的生产链为：

1. 基础构造0x1342f50写初始flags `0x31f8`。源TRS setter设置变换更新位；源可见状态与父级继承共同影响`flags & 0x18`。
2. 0x1362af0读取运行节点的原TRS，调用0x11dd3e0生成旋转矩阵，加入缩放和平移，得到local matrix（节点+0x68）。研究代码不归一化源四元数。
3. 0x1364674取得父级world matrix，在相应分支调用0x3732ac乘法，写world matrix（+0x28）；0x1364790写入包含`0x400`的flags，使世界盒需要刷新。无父级与单位矩阵优化也执行原分支。
4. 原回调0x34138c把实例TRS传给模型根节点，经0x1362320/0x139a2d0刷新后代。0x340f9c→0x337c98汇总符合条件的盒子。
5. 本批mesh在这些初始路径均满足`flags & 0x18 == 0x18`，且bit11为0。普通分支0x1362660→0x1113d60以原局部盒和原world matrix生成节点+0xd0世界盒，并清dirty位。

实验逐次记录原指令对节点+0x130的写入地址和值，而非只在末尾读取flags。另把box003源可见字**只在实验内存**改为0，原0x1362e80清bit3并影响子级汇总资格；原文件未改。这验证字段与继承条件的因果关系，不是要应用到游戏的新配置。没有穷尽未来所有flags写入者或恢复bit11的全部特殊路径。
