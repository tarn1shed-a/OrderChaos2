# 玩家共用入图链路

这批代码把原创角数据接到现有游戏服务器、存档、房间和网页地图。它不恢复原账号服务，不推定原服首次出生点、初始装备或已学技能。网页身份适配与原资源、原动作计算分别校验。

## 种族与职业

共用注册表包含九种原体型与五个职业，共 45 个明确的创角组合。Mendel、人类、精灵、兽人各有男女，Kartan 使用原表中存在的体型；不补造原表未有的性别组合。

`OC2_HUMAN_FEMALE_WORLD=1` 开启共用源角色链路。`OC2_SOURCE_WORLD_BODIES` 是明确的体型白名单；未设置时仍只开放此前的人类女性分支。解析白名单不代表实际原生准备、首帧、角色创建和浏览器绘制已经通过。每个组合必须经过同一个注册表、实际准备、当前连接首帧和入图能力检查。

其他八种体型使用各自原模型、材质、骨骼、属性绑定和动作区间。它们共用一个原生工作进程与实际源状态载体；人类女性保留其已核对的原初始化分支。现有旧角色继续原分支，不重解释为新的源角色。新旧角色共用原服务器、房间时钟、存档和任务账本。

入图等待的是当前演员实际消费的姿势。断线、重新选角、连接代次改变、地图销毁和晚到资源都经过同一生命周期检查。网页不重写原生姿势值，不另建动作计时循环。

## 移动、跳跃与采集

移动和跳跃沿用已核对的原输入、动作队列及物理执行。不同体型的原动作差异来自数据；额外的 `jump_start_01` 区间也保留独立原出处。

任务 461 使用用户已授权的兼容执行层，其原文字、目标和固定奖励保持。人类女性和旧精灵女性的采集绑定保留；其余八种体型由同一原索引生成正常动作、采集数据和独立绑定，接入同一个服务器门与表现核心。采集开关两侧都使用同一正常动作入口，不能退回旧绑定。

网页只观察既有权威状态包和实际已加载的采集库。当前演员须落地、无跳跃或施法，两层进入自身站立变体，且 current/previous 都能由该库承载；零权重也不删除前序动作。这只处理输入顺序。服务器另核当前演员所有者、真实队列、原生步骤开始前的姿态与随机状态，以及任务资格和结算。只读观察器委托同一个原步骤，不强制站立、不补 tick、不推进时钟、不改 RNG。

208 主线缺失环节继续取证，不简化接通。227 的击杀、掉落和批准不补造。NPC 出现与任务接取也不根据静态模型表推定。

## 技能与进度边界

职业目录和原技能窗口资源可以按当前已认证职业显示。原服初始已学技能、已装备技能和部分施法属性消息尚缺，不能把创角职业或 `hotbar: null` 当作技能授权，也不能套用旧法师默认技能。未核实的源技能请求继续拒绝。

461 的兼容奖励保存在现有任务账本。累计奖励经验不等同原版的当前等级经验，不套用试玩升级曲线，也不把账本物品写入尚无原槽位/GUID依据的角色容器。

## 验收与发布

已在同一 Linux 服务实际验证 45 组合的 HTTP 创角、认证 WS 入图与移动，九体跳跃/落地与位置恢复，以及七种不同身体同房、退出后的存活。当前仍使用同一个加载器和实际原生计算；测试没有导入生产存档。

精灵男性游侠已实际走完网页创角、开始、NPC 原正文接取、点击行走、四次原采集、两次原交回确认、原奖励与刷新恢复。实际渲染后的 82 个属性、298 个分量与同一原生事件流逐项一致，14 个可见蒙皮网格已链接并绘制。另一次双连接 HTTP 流程保留重启前的 4/4，重启后正常交回；重复领奖被拒绝。其余体型的采集与新绑定画面按同一批验收清单核对，不能仅据底层解析通过就称全部完成。

原资源和私有素材包留在忽略目录，不提交 Git。发布前必须核对实际 Linux 内存、CI、部署对应版本和生产存档；本批未通过完整实际验收前不更新 Railway。旧自动续跑保持暂停。
