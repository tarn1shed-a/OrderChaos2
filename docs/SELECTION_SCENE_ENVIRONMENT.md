# 选角背景的原环境输入

本批确认 map7 的原相机位置会选中区域 **211**，没有子区域覆盖；整理了其原色调、光照和雾输入。只生成独立证据，没有修改选角候选、新手地图、天空、发布配置或存档。

## 实际原调用与选择

原 `0x53ba74–0x53ba78` 从 GOT `0x2506870` 取得 `0x252773c`，此处保存原配置中的相机位置。原 `0x53bc78–0x53bc94` 依次请求重建区域目录、再调用：

`4c4cd0(environment, deltaMs=0, position=cameraPosition, forceFlags=1)`

这里 **0 是帧增量，不是环境模式**；1 是强制查询位。已执行这段原指令，记录真实参数，并独立执行原刷新函数，确认查询、声音和天气请求的次序；声音/天气/实际上传是记录边界，不冒充已执行。

`zones.tbl` 的 map7 原基础目录为 211、422、453、463。以源过滤目录为明确输入，原 `0x4c4de4` 的 phase、矩形比较和优先级选择代码实际执行后：原相机、原 `sceneCenter` 和原人物位置都选择 211。矩形只比较 X/Z，Y 不参与。完整原表没有 parent=211 的记录，不借其它地图或远处区域当作覆盖。

当前执行没有冒充原完整目录加载器、表解析器或活动覆盖映射；原表字节和结构核对、源目录筛选、原比较代码执行是三项分别标明的证据。

## 原字段及消费

| 输入 | 原结果与核查 |
|---|---|
| 环境光、方向光、角色/场景强度、色调 | 复用原区域目标消费者，13 个通道的 ARM64 写入实际执行；区域 211 自己的值，不沿用 map5 |
| 色调距离 | 原 `[0,17]`，送入材质的距离参数为 `[0,-1/17]` |
| 近/远色调 | 原 packed RGB 转浮点后的各自颜色；不是统一白色或手动提亮 |
| 模型 lightmap 强度 | 源字段零值触发原库默认 `float32(1.33)`；模型强度按原同一所有者分支继承 |
| 模型光颜色 | 原完整 RGB 生产函数 `0x34e53c` 在**显式零附加量**前提下提交约 `[1.995,1.924588,1.820275]`；不是实际天气附加量永远为零的证明 |
| 雾 | APK 默认雾配置下，原雾代码提交近端 58、半衰距离 148、RGB 约 `[0.729412,0.819608,0.878431]` |
| 天气 | 原区域 weather=0、extra=0、festival 为空；说明本区域不请求这些天气效果，不证明重进选角前没有旧天气历史 |
| 天空、远山、bloom | 保留区域 211 的原引用和字段，本批没有激活，也没有用 tutorial 天空/参数替代 |

原目标函数通过 `world+0x178 → +0x58 → +0x40` 判断立即更新还是 2000ms 过渡。已分别执行缺对象、数值 0 和数值 4 的原目标写入，验证前两者立即、4 建队列，且最终目标相同。2000ms 后的稳定状态由先前已核队列数值模型计算；没有把它说成真实原客户端经过 2000ms 的画面或本批完整原帧执行。

## 最小导出接口与缺口

[`selection_scene_environment_probe.py`](../tools/selection_scene_environment_probe.py) 的 `report(image, source_path)` 生成完整证据，`export_inputs(evidence)` 仅导出本场景所需的原目标、稳定状态、默认条件下的雾和待补运行输入。输出 `inputs.json` **不创建 Three 灯光、相机或环境**，并保留 `originalRuntimeContextReady=false`。

这不是缺一张需要用户补画的光照图。当前具体上游缺口是：原刷新前的模式对象值、旧环境队列是否已清空、渲染器 RGB 附加量/天气历史、雾的运行时配置、环境上传字节，以及可能的目录覆盖。后续沿 `53b5c8 → 4d7c04 → 4c1ac4 → 4c4cd0` 的实际生产者继续查；不把“没有原 Android 运行现场”本身作为永久停止理由，也不猜零值把字段强行接满。
