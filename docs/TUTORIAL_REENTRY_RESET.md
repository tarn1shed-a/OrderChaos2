## 先真实掉落，再设置位置

复用上一批神殿原屋顶支撑点和连续 +Z 行走输入，不重复几何统计，也没读用户录屏作为运动输入。原静态 PHY、原重力和碰撞实际执行；速度 4.8 与 50 ms 步长是网页宿主输入。

- 途中点为 `(-2611.410156,165.217148,248.482635)`，正在下落，竖直速度约 `-17.675`、加速度约 `-6.7`。
- 仅原 setter，或原 `9037d4` 前段加 `90c348`，都会把 XYZ 改为 w7，但**立即检查仍保留上述速度/加速度**。随后一帧原碰撞在庭院真实支撑上落地，速度才归零。
- 另一个同样真实下落的正常 Hero 夹具，完整执行 `9037d4`、原两段单例构造并返回，仍保留旧速度/加速度。第二次调用已有单例分支结果相同。因此该结论不只是停在构造器前得到的假象；不扩大到未执行的其它入图回调。
- 完整掉落后，源屋顶 `172.366898` 到下层 `132.349991` 相差 `40.016907`。该真实落地状态再执行原前段和支撑查询，也能保持庭院；没有假安全地板或原服目的地。
- 实际原跳跃准备后，Y 为 `136.229996`、速度约 `7.92`。同一前段把位置设回庭院，但速度仍在，下一帧升到 `136.125992`。这直接说明“改坐标”不等于复位运动。
- 实际潜水准备后水态为 4、相机水下标志为 true。原前段保留水态和相机块；`90c348` 的原支撑查询把水态改为 0，保留原水面高度元数据。后续相机原帧清水下标志，但保留玩家原有俯仰 `315°` 和朝向 `-90°`；本批没有手动复位相机字段。

## 新网页实体为什么重要

额外执行当前原 127 审定的真实 `native-window-collision.mjs` 中 `bind` 函数，文件 SHA 为 `63ef96740c801b6c4e5887bbdff585c31404582c07a59e523fd8769721bbfb1e`；`source-shore-motion.js` 为 `510c6912f79883a778114779a8f0e17b30dc9e042d1238572b9fb2016a43d9ea`。这里只注入记录 RPC/世界参数，不称原物理或浏览器执行。

- 同一角色 ID、**新 JS 对象**首 move 的实际调用是 `reset → tick`。旧对象在 WeakMap 里未消费的跳跃、镜头输入不会跟过去；首 tick 的 jump=false，control 只有 forward=false。第二次 move 只有 tick。
- **旧对象只 restoreHeight** 会清 initialized，从而也发物理 reset，但不会清 pending WeakMap。若之前已请求跳跃、积累镜头 delta，首 tick 仍会发送它们。本批负对照实际录到 jump=true、yawDelta=19。

因此父任务运输接线需要真实等待当前会话释放、保持身份守卫、重连创建新对象，并清旧移动输入/浏览器镜头与呈现缓冲；不能只调用 restoreHeight 或改磁盘。存档备份和位置唯一修改仍沿 [CHARACTER_POSITION_RESTORE.md](CHARACTER_POSITION_RESTORE.md) 与 [UNSTUCK_RETURN_ADAPTER.md](UNSTUCK_RETURN_ADAPTER.md) 的既有边界执行，本批没有做这些操作。
