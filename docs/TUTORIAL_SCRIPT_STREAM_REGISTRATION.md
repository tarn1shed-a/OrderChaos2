## 缓存不是别名或解码器

`54bc84` 首先调用 `54bf70` 查文件系统 `+e0` 的树，树头为 `+e8`。键是原输入复制成的 C++ 字符串，按 `memcmp` 和长度比较；本段没有转小写、替换斜线或改名。这与归档内部另有规范化规则的 `54c604` 要分开。

真实填表者为 `54c180`：先查同一缓存；没命中才调用同一个文件系统的原 `v+18` 打开；**只有返回非空流，才经 `55d400` 插入缓存**。这不是拿一段外部字节或别名直接生成新文件的入口。

原 `9daab4` 销毁任务时，经 `54c2dc` 按流指针移除缓存项；`54c36c` 清空整树。Ghidra 的 `.eh_frame/.eh_frame_hdr` 引用已单独标成展开元数据，不能拿它们冒充额外运行时注册调用。
