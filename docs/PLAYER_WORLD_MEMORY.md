# 玩家执行资源与内存

本轮只优化宿主加载和数据保留，不改原 ARM64 指令、物理、动作队列、采样、随机状态或存档。原库、模型、动画、地形和碰撞资源字节保持；旧自动续跑暂停，Railway 未更新。

此前八体已共用一个 Python 工作进程和同一加载器，但进程内部为每体重新创建了 `NativeImage`，重复保留原库字节、ELF 解析、函数索引和导入表。人物原生预处理完成后，compositor 还保留整份转换模型 JSON，包括运行时不再读取的网格和预转换片段。

现在每个串行 RPC 所有者只创建一份经原构造器校验的 `NativeImage`。各体型仍检查自己的原输入；每个 Uc、全局数据、堆、场景、角色和 compositor 均保持独立。完整原生预处理、绑定和检查结束后，compositor 的 `data` 仅保留四个运行时 `compose_values` 消费者实际读取的 `rig.skins[*].boneNames`；已建立的原生缓冲、动作库、遮罩、轨道和绑定不动。单独加载时 `resources=None` 保留完整资料与独立 Image，供兼容及对照。

启动器和 Node 运行端从同一份 `tools/source_world_python.json` 的 `plans.latestWorld` 读取素材计划路径、大小和 SHA。打包器更新一处声明，消除手工同步两份校验值的依赖。

在同一 Linux/amd64 Docker 环境，基线和候选分别冷启动、使用独立空 QA 卷，以同一个冻结驱动和原九体注册表创建角色、认证入图并观察实际原生包。九个角色各处单独房间，同时驻留后采样，再全部关闭并观察三秒。此场景不发送移动或跳跃，不宣称九人同时移动通过。没有设置本地 CPU/RAM 上限、清空内核缓存或导入现有玩家存档。

| 九体同时驻留 | 基线 | 资源优化后 |
| --- | ---: | ---: |
| 进程 PSS 合计，含小型读取器 | 2.446 GiB | 1.880 GiB |
| 匿名内存 | 2.377 GiB | 1.810 GiB |
| 其中八体 Python 进程 PSS | 1766.1 MiB | 1193.5 MiB |
| 内核文件缓存 | 0.771 GiB | 1.578 GiB |
| cgroup `memory.current` | 3.217 GiB | 3.475 GiB |

进程 PSS 减少 607,830,016 字节（约 579.7 MiB、23.1%）。本次文件缓存更多，因此 cgroup 总用量反而增加，不能据此称 Docker 总内存下降。全部断开后三秒的 PSS 仍约 1.882 GiB，说明已准备的执行核心仍驻留。

剩余主要占用包括各体型独立的原生控制/物理与骨骼执行状态、人类女性原有独立执行分支、旧角色物理进程和 Node 资源。每个 Uc 还独立映射约 36 MiB 的原 RX 段。共享代码页的小型本机隔离原型未通过，未接入游戏；没有为节省内存合并可写状态。

原生计算对照已完成：八体使用同一实际配置，基线关闭静态资料池、候选开启，分两个顺序进程执行 279 个原生 tick、1148 次 RPC。位置、队列、float32 骨骼结果、随机状态、采集上下文及完整内部快照逐项相同；静态 Image 实例由八份变一份。两个测试进程使用相同 Python 哈希种子，避免宿主 set 迭代顺序改变控制对象分配地址；服务配置与原生随机数未改。

辅助 RX 日志的旧实例编号器使用 `id(uc)`，临时对象释放后地址复用，导致最后一条编号 17/16 不同，旧汇总检查因此仍报失败，原报告保留。17 条实际写入的地址、长度、调用点，以及每个执行核心最终原代码字节均相同。独立修正后的 QA 编号器通过六组生命周期检查，含 17 个小型 Uc 和九次实际地址复用；未以删除游戏字段或改写快照来通过对照。

优化版已在本地 Linux 服务完成一次实际浏览器流程：新建人类男性游侠、入图绘制、点击及方向键行走、跳跃、接取 461、四次采集、两步原交回确认、领奖、刷新后重新登录入图。隔离账本保留 completed、四个已采对象及原奖励 512 经验、9 货币、5 声望和一件 20028；累计奖励未写入未知的原等级经验规则。旧 QA 两份存档在本轮对照前后逐字节相同，没有导入或修改生产存档。

上述浏览器验收覆盖一个代表体型；八体原生计算与九体驻留测量另列，未重复声称九人同时移动或完整职业战斗已经通过。九体进程 PSS 仍高于 1 GiB，未证明当前线上容量足够。本批保留为已本地验收的候选，不更新 Railway 或费用设置。

后续按实际线上约 1 GB RAM、零交换空间条件补验：同一人类女性体型的五个职业、五个新隔离角色同时在一个房间，收到各自及同伴的原 1928 字节姿势和三个自然状态帧。只有一个人类女性执行进程，未按职业复制核心。五人同时在线时进程 PSS 合计 680.9 MiB，匿名内存 660.3 MiB，文件缓存 240.9 MiB，容器总量 937.8 MiB；交换用量、OOM 和重启均为零。全部退出三秒后 PSS 仍为 681.3 MiB，说明执行核心继续保留。冷准备的首帧耗时 11.7 秒，其后四次首帧约 190–283 毫秒；没有发送移动输入，不作为动作延迟或长期并发验收。

这区分了职业数、同时在线角色数与已准备体型数：五职业共用一个体型核心的占用，不能按五份完整执行核心相加；同样也不能把本次单体型通过外推成九体型能在该上限内运行。先前本地允许交换空间的一轮另行保留，仅以本次零交换结果作为与线上容量的有界对照。
