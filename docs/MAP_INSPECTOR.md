# 管理员地图巡查

这是用户明确要求的网页管理工具，不属于原版玩法或逆向还原成果。普通玩家不显示工具条、不获得飞行或穿墙权限。

管理员登录 `/admin/` 后选择“进入地图巡查”。服务器首次创建一个独立的“地图管理员”角色，并把 UUID 和恢复凭据保存在私有 `/data/map-inspector.json`；后续复用同一角色。权限按服务器登记的 UUID 和已验证角色对象判断，名字、网址参数和客户端字段都不能授予权限。凭据仅由同源、已登录后台的 POST 返回，禁止缓存，不写入网页普通角色列表。

操作：WASD/方向键移动，空格上升，Ctrl下降，Shift加速，拖动旋转视角，滚轮缩放，R返回已授权的 cinematic7 庭院。速度、无碰撞相机和地图边界限制都是管理工具适配，不能标成原代码。庭院有原过场与支撑依据，仍不是已确认的原版首次出生点。

普通角色继续调用原碰撞和相机。巡查角色只绕过自己的移动碰撞，使用单独的 `inspectionCamera`，不伪造 `nativeCPU` 标记；不可攻击、拾取或更改装备、任务、技能。350毫秒失去输入即停止；切到后台或打开界面也停止。巡查中的位置不写入角色存档，下次进入从庭院重新开始，避免穿地位置污染正常游玩。

`deploy/role_position_repair.mjs` 是另一个启动时维护工具，没有公开接口。只消费私有文件中的指定 UUID、名字、预期旧位置及固定庭院目标；拒绝已变化的旧位置，只修改 `positions.resources`，成功后将请求改名为 `.applied` 并记录其它字段的校验值。用户明确允许角色“2”复位并要求不另做备份，本次不删除角色、不重置进度、不额外保存完整存档副本。

验证使用 `node --test tools/map_inspector_tests.mjs tools/admin_tests.mjs`，以及独立 Linux 卷的真实双连接与浏览器键盘测试。原资源、私有权限文件、凭据、截图和存档均不上传 GitHub。实际生产发布以目录最新收据为准。
